# Threads 웹 발행 운영

Threads 웹은 브라우저 자동화로 다루기에 함정이 많다. 여기 있는 것은 전부 실제로 한 번씩 사고를 내고 알아낸 것들이다.

전제: 로그인 세션에 붙는 브라우저 도구로 조작한다. 상세 문서의 항목에는 확인에 쓴 도구를 적어두었다 — 2026-07-27·07-29 실측은 **claude-in-chrome**, 2026-07-31과 08-01 일부는 **Aside repl**, 08-01 사진·업로드 실패 항목은 다시 **claude-in-chrome**이며 인용카드 항목은 두 도구로 교차 확인했다. 관측이 엇갈릴 때 도구를 바꿔 재현하면 원인을 가릴 수 있으니 도구명을 지우지 말 것.

공식 API는 예약 발행을 지원하지 않는다. 예약이 필요하면 웹을 쓴다.

## 절대 규칙 5개

이건 매번 적용한다. 나머지는 상황에 맞는 상세 문서를 열어 본다.

1. **작업 중 새로고침 금지.** `page.reload()`는 작성 중 상태를 초기화하고 ref를 전부 무효화한다. 상태 확인은 새 `snapshot()`이나 `screenshot()`으로 한다. 새로고침은 작업이 끝나고 최종 검증할 때 한 번만.

2. **모든 편집 칸은 `.`으로 시작**해 타이핑하고, 끝나면 맨 앞 1글자를 지운다. **단 이 잘림은 도구별이다** — claude-in-chrome에서는 거의 매번 일어나지만, **Aside repl(Playwright `keyboard.type`)에서는 5회 시도에서 재현되지 않았다**(2026-08-25). Aside에서 가드는 무해하지만 필수가 아니고, 가드를 쓰면 "가드 제거가 유실 글자를 상쇄"하는 부작용(아래 함정)이 남으니 **문자 단위 대조는 어느 도구든 생략하지 않는다.**

3. **해시태그(주제 태그)는 글당 1개 모델로 바뀌었다** (2026-08-25 Aside repl 실측). 구 규칙 "`#태그 ` 공백이 경계를 만든다"는 현재 UI에서 성립하지 않는다 — **공백을 넣어도 첫 `#`부터 줄 끝까지 통째로 하나의 주제 태그**로 파싱되고, 태그 팝업이 뜬 상태에서 Enter를 치면 태그가 본문에서 빠져나가 모달 상단 `커뮤니티 또는 주제` 검색칸으로 승격된다(저장 결과는 미검증). 기본이 해시태그 0개라 실무 영향은 적지만, 태그를 쓸 거면 여러 개를 본문에 넣으려 하지 말 것.

4. **팝업은 X 버튼으로 닫는다(해시태그 팝업엔 X가 있고, 멘션 팝업엔 없다 — 멘션은 후보 클릭이나 커서 이동으로).** Escape는 조심한다: 팝업이 떠 있으면 첫 Escape는 팝업만 닫지만(2026-08-25 Aside 실측), **팝업이 없는 상태의 Escape는 작성창을 닫아** `임시 저장하시겠어요?` 확인창을 띄운다. 작업을 이어갈 때는 그 창에서 `취소`다. `저장 안 함`은 되돌릴 수 없다. 본문이 빈 작성창은 확인창 없이 그냥 닫힌다.

5. **추정 금지 — 확인할 수 있는 것은 확인한다.**
   - **댓글 뜻은 대화 전체를 시간순으로 펴서 정한다.** 목록·요약에 잘려 나온 한 줄로 판단하지 마라. 같은 댓글을 두 세션 연속 오독한 사례가 있다 — 앞 댓글이 잘린 채로만 보고 뒤 댓글만 읽은 것이 원인이었다. 판정은 `{id}/conversation` 전문으로 한다.
   - **사진·링크 유무를 규칙에서 역산하지 마라.** "브랜드 사진은 상시 첨부"가 규칙이어도 실제 첨부는 API `media_type`/`media_url`로 확인한다. 지표 표가 이것 때문에 3건 틀린 적이 있다.
   - **본 것으로 원인을 지어내지 마라.** 화면에 결과가 있다고 내가 한 것이 아니다. **사용자도 같은 브라우저를 조작한다.** DM이 차단됐다고 보고한 뒤 대화창에 메시지가 보이자 "차단됐는데도 나갔다"고 단정한 적이 있는데, 차단은 맞았고 사용자가 직접 보낸 것이었다. 관측은 옳고 인과가 틀리는 쪽이 더 위험하다 — 모르면 물어본다.
   - **시각은 행동 직전에 다시 찍는다** (`TZ=Asia/Seoul date`). 8시간 지난 초안의 `방금`을 그대로 발행할 뻔한 적이 있다.
   - 모르면 채우지 말고 `미확인`으로 표시해 사람에게 넘긴다.

## 계정 발행 규칙 (2026-08-06 사용자 지정)

1. **발행 간격 2시간** (2026-08-20 사장 지시로 3시간에서 조정). 예약이나 발행을 잡기 전에 반드시 ① 프로필 최신 글의 발행 시각과 ② 임시 저장본의 기존 예약 목록을 먼저 확인하고, 가장 늦은 시각 + 2시간 이후로 배치한다. 실제 사고: 기존 오후 7:00 예약을 확인하지 않고 7:30에 새 예약을 잡았다(30분 간격). 목록 확인이 먼저다.

   **간격을 말하기 전에 이 줄의 숫자를 읽어라.** 2026-08-22에 이 파일이 3시간으로 남아 있는 걸 그대로 믿고 "규칙 위반"이라고 사장에게 보고한 사고가 있었다. 실제로는 2시간이라 지켜진 상태였고, **맞는 말을 틀린 말로 정정한 셈**이 됐다. 규칙이 또 바뀌면 여기를 고치는 것까지가 작업이다 — 값의 출처는 세션 HANDOFF이고, 스킬이 뒤늦게 따라온다.

2. **사용자 예외 지시가 우선.** 사용자가 "게시해"라고 명시하면 간격 규칙과 상관없이 즉시 게시한다. 예외는 그 1회에만 적용되고 규칙 자체는 유지된다.

## 가장 비싼 함정 4개

상세 문서를 열기 전에 이 네 개만 기억해도 큰 사고는 막는다.

**인라인 답글창에서 Enter는 줄바꿈이 아니라 발행이다.** 줄바꿈이 섞인 문자열을 그대로 타이핑하면 첫 줄만 올라가고 나머지는 사라진다. 여러 줄은 확장(⤢) 창이나 수정 창에서 쓴다. 인라인을 꼭 써야 하면 `Shift+Enter`. **확장(⤢) 버튼은 답글을 달 때만 나온다** — 새 글 작성 모달에는 없다(`composing.md` §1).

**`@`로 시작하는 낱말은 전부 멘션이 되고, 자동완성 팝업이 떠 있으면 Enter가 줄바꿈이 아니라 후보 선택이다.** 팝업은 **후보를 클릭해 확정**한다. 명령어에 들어간 스코프 패키지명(`@bitkyc08/opencodex`)도 링크가 되므로 피할 수 없다(`composing.md` §1).

**사진 첨부 경로는 도구에 따라 갈린다** (2026-08-25 교차 실측). **claude-in-chrome은 클립보드가 유일한 경로다** — 파일 업로드 도구는 거부되므로 macOS에서 `osascript`로 클립보드에 올린 뒤 `Cmd+V`. 반대로 **Aside(aside CLI) 샌드박스는 `osascript`가 막히고 Playwright `setInputFiles` 직접 첨부가 통한다** — Threads와 래피드 양쪽에서 확인됐다(`composing.md` §3). 공통 규칙: webp는 받지 않으므로 `sips`로 PNG 변환하고, 실사 사진은 PNG로 바꾸지 말고 **JPEG 그대로 긴 변 2000px 이내로 줄여** 붙인다 — PNG 변환은 용량을 몇 배로 키워 업로드 실패를 부른다(`composing.md` §3).

**인용카드가 붙으면 예약이 안 된다.** 링크 미리보기 카드는 예약을 막지 않지만 Threads 인용카드(share URL)는 `예약...`을 비활성으로 만든다. 메뉴는 열리고 항목도 보이므로 눈으로는 안 걸린다. 판정은 DOM으로 한다.

**글자 수가 맞아도 글자가 빠져 있을 수 있다.** 가드 `.`을 지우는 절차가 타이핑 중 유실된 한 글자를 상쇄해, 218자가 초안과 정확히 일치하는데도 본문은 `코드가`가 `드가`로 저장돼 있었다. 검증은 총합이 아니라 **문자 단위 대조**로 한다.

## 발행 전 점검

- [ ] 답글이라면 확장 창에서 썼는가 (인라인 Enter로 반쪽만 올라가지 않았는가)
- [ ] `@`가 들어간 칸이라면 멘션 팝업을 **클릭으로 확정**하고, 붙어 나온 꼬리 공백을 지웠는가
- [ ] 전문을 `innerText`로 검증했는가 (한글 오타, **잘린 앞 글자**, **뭉친 해시태그**)
- [ ] 각 칸을 초안과 **문자 단위로 대조**했는가 — 글자 수만 맞춰보면 안 된다. 가드 `.`을 지운 것이 타이핑 중 유실된 글자를 상쇄해 총합이 맞아떨어진 사례가 있다(`composing.md` §2)
- [ ] 자답글을 `스레드에 추가`로 묶었는가 (칸 번호 `n/N`로 확인)
- [ ] 사진마다 alt를 넣었는가 (입력 전 `contenteditable` 인덱스를 확인했는가)
- [ ] 다중 이미지의 세로 비율이 비슷한가 (다르면 같은 비율로 패딩했는가 — **단독 1장은 원본 비율 그대로, 4:5 패딩은 2장 이상일 때만**, 2026-08-26 사장 확정)
- [ ] 첨부가 무겁지 않은가 (합계 12MB에서 업로드가 실패한 사례가 있다 — `composing.md` §3)
- [ ] 사진이 눕지 않았는가 (EXIF orientation 이중 적용 — `composing.md` §3)
- [ ] alt는 라벨이 아니라 **다시 열어** 확인했는가 (저장돼도 `대체 텍스트 추가`로 남는다) — **발행되면 alt는 수정 불가이므로 이 확인이 마지막 기회다**
- [ ] **해시태그를 안 붙였는가** — 기본은 0개다. 150건 대조에서 조회 중앙값이 910(있음) vs 902(없음)로 차이가 없었다(`threads-linebreak` §5.6). 일부러 붙이는 경우에만 본문 마지막 단독 문단, 자답글에는 0개
- [ ] 프로필 최신 글과 **임시 저장본 예약 목록**을 확인하고 2시간 간격으로 배치했는가 (사용자가 "게시해"라고 하면 예외)
- [ ] 예약이라면 배너와 `예약` 버튼을 눈으로 확인했는가
- [ ] 예약이라면 인용카드가 안 붙어 있는가 (붙었다면 `예약...` 상태를 DOM으로 확인)
- [ ] 링크 카드를 뗀 글이라면 **마지막 `업데이트` 직전에** 다시 확인했는가 — 편집 모드로 열 때마다 카드가 재생성된다 (`scheduling.md` 링크 카드 항목)
- [ ] 인용카드가 필요한 글인가 (임시 저장은 카드를 보존하지 않으니 게시 직전에 다시 붙였는가)
- [ ] 인용카드를 붙일 칸에 이미지가 없는가 (한 칸에서 양립 불가)
- [ ] `(no name)` 버튼을 누르기 전에 정체를 DOM으로 확인했는가
- [ ] 답글 고정을 교체했다면 확인창의 `확인`을 눌렀는가 (`고정됨` 배지로 검증)
- [ ] DM 소재라면 발화자를 좌우 좌표로 갈랐는가
- [ ] DM 소재라면 입력 경로(음성/키보드) 분류를 **사용자에게 확인받았는가** — 문장부호는 단서일 뿐 규칙이 아니다
- [ ] DM 소재라면 게재·인용 동의를 받았는가

**사용자가 "게시된 것 같다"고 말하면 그 말이 내 화면 판단보다 우선한다.** 즉시 피드를 확인하고, 확인될 때까지 다음 입력을 하지 않는다.

## 발행 후 검증 — 공식 API는 16분 뒤에 본다 (2026-08-22)

**Threads의 게시물 수정 가능 시간은 발행 후 15분이다.** 그 안에 공식 API로 읽은 값은 아직 확정된 것이 아니다 — 그 사이에 본인이 고치거나 사용자가 고치면 방금 "검증 완료"라고 보고한 내용과 실제 글이 달라진다.

> **발행 검증용 API 조회는 발행 시각 + 16분 이후에 한다.**

- 발행 **직후**에 확인할 것은 **화면**이다 — 칸 번호 `n/N`, 사진 썸네일, 카드 제거 상태를 눈으로 본다. 이건 즉시 해도 된다.
- **문자 단위 대조·`media_type`/`media_url`·`alt_text` 확정 판정은 +16분 이후 API로** 한다. 그때가 되어야 "이 글은 이 내용으로 굳었다"고 말할 수 있다.
- 15분 안에 오타를 발견했다면 그게 고칠 수 있는 마지막 창이다. **`alt`는 발행되면 수정 불가**이므로 이 창에도 해당되지 않는다 — alt는 발행 전에 끝낸다.
