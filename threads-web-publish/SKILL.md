# Threads 웹 발행 운영

Threads 웹은 브라우저 자동화로 다루기에 함정이 많다. 아래는 전부 실제로 한 번씩 사고를 내고 알아낸 것들이다. 순서대로 따라가면 같은 값을 다시 치르지 않는다.

전제: 로그인 세션에 붙는 브라우저 도구로 조작한다. 아래 항목에는 확인에 쓴 도구를 함께 적어두었다 — 2026-07-27·07-29 실측은 **claude-in-chrome**, 2026-07-31 실측은 **Aside repl**이며 §6의 카드 항목은 두 도구로 교차 확인했다. 관측이 엇갈릴 때 도구를 바꿔 재현하면 원인을 가릴 수 있으니 도구명을 지우지 말 것. 공식 API는 예약 발행을 지원하지 않으므로(§8) 예약이 필요하면 웹을 쓴다.

**작업 중 새로고침 금지 (2026-07-31, Aside repl).** 입력·편집·클릭 도중 `page.reload()`를 하면 작성 중 상태가 초기화되고 ref가 전부 무효화되어 같은 작업을 처음부터 다시 해야 한다. 상태 확인은 새로고침이 아니라 새 `snapshot()`이나 `screenshot()`으로 한다. 새로고침은 한 작업이 끝나고 결과를 최종 검증할 때 한 번만 쓴다.

## 1. 본문 입력 — 인라인 Enter는 즉시 게시다

가장 비싼 함정부터. **인라인 답글창에서 Enter는 줄바꿈이 아니라 발행이다.** 줄바꿈이 섞인 문자열을 그대로 타이핑하면 첫 줄만 올라가고 나머지는 사라진다.

- 여러 줄은 **확장(⤢) 창이나 수정 창**에서 쓴다. 거기서는 Enter가 줄바꿈으로 동작한다.
- 인라인 창을 꼭 써야 하면 줄바꿈을 `Shift+Enter`로 넣는다.

**여러 줄을 넣을 때는 브라우저 도구의 `type` 액션으로 줄바꿈을 포함해 통째로 입력한다.** 모달 작성창에서는 Enter가 줄바꿈이라 이게 가장 확실하다.

`execCommand`로는 줄바꿈이 들어가지 않는다 — 2026-07-27 실측:

- `document.execCommand('insertText', false, '...\n...')` → **`\n`이 통째로 무시되고 한 문단으로 뭉친다.** 글자는 다 들어가는데 줄 구조만 사라져서, 확인 없이 게시하면 문단 없는 벽 글이 올라간다.
- `document.execCommand('insertLineBreak')`를 줄 사이에 끼워도 → 역시 줄바꿈이 안 생기고, 커서가 튀어 문장 순서까지 뒤섞였다.

한 줄짜리 텍스트를 넣거나, 이미 있는 오타를 Range 선택 후 바꿔치기할 때는 `insertText`가 여전히 가장 안전하다(Lexical 에디터라 DOM 직접 주입은 저장 시점에 날아간다). 즉 **줄바꿈이 없으면 `insertText`, 있으면 `type`**.

작성창을 먼저 클릭해 포커스를 준다. 그리고 **클릭 직후 바로 타이핑하면 앞 글자가 잘린다** — `같은 `이 통째로 날아간 적이 있고, 2026-07-29에도 본문 첫 줄 `사용량이 `가 그대로 유실됐다.

이건 가끔이 아니라 **거의 매번**이다. 그래서 방어를 절차에 박아둔다:

> **모든 편집 칸은 `.`으로 시작해서 타이핑하고, 입력이 끝나면 맨 앞 1글자를 지운다.**

```javascript
// 맨 앞 한 글자 제거
const el = document.querySelectorAll('div[role="dialog"] div[contenteditable="true"]')[i];
el.focus();
const first = document.createTreeWalker(el, NodeFilter.SHOW_TEXT).nextNode();
const r = document.createRange(); r.setStart(first,0); r.setEnd(first,1);
const s = getSelection(); s.removeAllRanges(); s.addRange(r);
document.execCommand('delete');
```

잘림이 나도 잃는 건 `.` 하나다. 지우기 전후로 `innerText` 앞부분을 찍어 확인한다.

한글은 **리터럴로 넘긴다.** 도구 인자에 `\uXXXX` 이스케이프로 넘기면 코드포인트를 틀려 오타가 난다(블로그→바로그, 간격→간겁). 게시 전에 전문을 검증하고, 오타는 TreeWalker로 텍스트 노드를 찾아 Range 선택 후 `insertText`로 교체한다.

### 해시태그 — 공백이 경계를 만든다

해시태그를 치면 주제 태그 자동완성 팝업이 뜬다. 전체 문자열을 하나의 태그로 만들려 한다.

**`Escape`로 팝업을 닫아도 토큰 경계는 안 생긴다.** 2026-07-29 실측: `#코덱스` → Escape → `#장애인` → Escape … 순으로 넣었더니 저장 시점에 **`#장애인접근성디버깅바이브코딩` 한 덩어리로 병합**됐다. 화면에는 태그처럼 보여서 눈으로는 안 걸리고, `innerText` 검증에서만 잡힌다.

경계를 만드는 것은 Escape가 아니라 **뒤따르는 공백**이다:

> **`#태그 ` 단위로, 뒤 공백까지 붙여 하나씩 넣는다.** 매 태그 후 `innerText` 마지막 줄을 확인한다.

이미 뭉친 토큰은 부분 교체가 덧붙는 식으로 깨지므로(`#장에인#장애인`), 캐럿을 뒤에 놓고 글자 수만큼 `BackSpace`로 지운 뒤 다시 넣는다.

### Escape는 작성창까지 닫는다

**팝업만 닫으려고 누른 `Escape`가 작성창을 닫는다.** 2026-07-29에 이걸로 `임시 저장하시겠어요?` 확인창이 떴다.

- **팝업은 X 버튼으로 닫는다.** Escape에 의존하지 않는다.
- 확인창이 뜨면 **작업을 이어갈 때는 `취소`**다. `저장 안 함`은 되돌릴 수 없다.
- 확인창이 2개 겹쳐 뜨는 경우가 있다. 하나 닫고 스크린샷으로 재확인한다.

임시 저장은 잘 버틴다 — 창이 닫혀도 본문·줄바꿈은 임시 저장본에 남았다. 다만 **뭉친 해시태그는 뭉친 채로 저장된다.** 저장이 내용을 고쳐주지는 않는다.

`Cmd+A`는 편집 영역 안을 클릭한 뒤에 눌러야 한다. 사진이나 여백을 클릭한 상태면 페이지 전체가 선택된다.

### 내용 검증

```javascript
const e = document.querySelectorAll('div[contenteditable="true"]');
const n = s => s.replace(/\n/g,'').replace(/ /g,' ').trim().length;
Array.from(e).map((el,i) => `${i+1}=${n(el.innerText)}자`).join(' / ')
```

글자 수는 **줄바꿈 제외**로 센다. 줄바꿈을 늘려도 길이 계산에 영향이 없다.

## 2. 자답글은 `스레드에 추가`로 묶는다

여러 편으로 나눌 글은 확장 창의 **`스레드에 추가`** 버튼으로 칸을 늘려 한 번에 게시한다. 따로따로 올리면 체인이 아니라 형제 답글로 흩어져 순서가 뒤섞인다.

한 번에 게시되므로 "자답글을 본문 직후에 올린다"는 조건도 자동으로 충족된다. 3일 늦게 단 자답글은 조회가 거의 안 붙는다.

## 3. 사진 첨부 — 클립보드가 유일한 경로

에이전트가 파일 업로드 도구로 직접 올리는 건 거부된다(세션에 공유된 파일만 허용). 프로젝트 폴더도, 스크래치패드도 안 된다. macOS에서는 클립보드로 우회한다:

```bash
osascript -e 'set the clipboard to (read (POSIX file "/절대/경로/파일.png") as «class PNGf»)'
```

그 뒤 작성창 텍스트 영역을 클릭하고 `Cmd+V`.

- **webp는 Threads가 안 받는다.** `sips -s format png 원본.webp --out 결과.png`로 변환한다.
- 폰 스크린샷은 맥에 파일이 없다. 메신저로 옮기면 확장자가 `.webp`로 오는 경우가 많다.

## 4. 다중 이미지는 세로 타일로 센터 크롭된다

사진이 2장 이상이면 캐러셀로 묶이며 **세로 타일 기준으로 잘린다.**

- **가로로 납작한 이미지(예: 472×54 메뉴바 크롭)는 쓰지 말 것.** 핵심 숫자가 전부 잘리고 가운데 파편만 확대된다.
- 비교용 2장은 **비슷한 세로 비율끼리** 묶어야 둘 다 읽힌다(786×1204 + 802×1252 조합은 정상).
- 납작한 이미지를 꼭 써야 하면 단독 1장으로 올리거나 정사각형으로 패딩한다.

## 5. alt 텍스트

사진 위에 마우스를 올리면 좌하단에 `···`이 뜬다 → **`대체 텍스트 추가`** → 입력 → `완료`.

**`···`가 화면 밖에 있으면 hover로도 안 나온다.** 세로로 긴 이미지는 작성창을 스크롤해 이미지 하단이 보이게 한 뒤 hover해야 한다. 안 보이면 스크롤부터 의심한다.

- 사진이 여러 장이면 **각 사진마다 따로** 넣는다.
- **길이 제한은 넉넉하다** — 581자가 잘림 없이 들어갔다(2026-07-29). 줄바꿈 없는 한 문단이므로 `insertText`로 통째로 넣으면 된다.
- alt 입력란도 `contenteditable`이라 본문 칸과 같이 잡힌다. **인덱스를 확인하고 쓸 것** — 본문 칸에 alt를 쓰는 사고가 난다.
- 예약 저장 후 다시 열면 이미지 `src`가 `blob:`에서 `https://scontent-...`로 바뀐다. **`blob:`만 세는 검증 스크립트는 0을 반환한다** — 첨부가 사라진 게 아니다.

```javascript
Array.from(document.querySelectorAll('div[role="dialog"] img'))
  .filter(i => i.width > 100)
  .map(i => `${i.width}x${i.height} alt=${(i.alt||'').length}자`)
```

## 6. 예약 발행

작성창 우측 상단 `···` → **`예약...`** → 달력에서 날짜 클릭 → 하단 시간 입력(`15 : 00` 형식, 시·분 각각 삼중클릭 후 타이핑) → `완료`.

설정되면 상단에 `수요일 오후 7:00 GMT+9에 게시 예정` 배너가 뜨고, 하단 버튼이 `게시` → **`예약`**으로 바뀐다. `게시물 옵션`은 답글 권한 설정이라 예약과 무관하다.

### 예약을 막는 건 인용카드다. 링크 카드는 막지 않는다

**인용글은 예약이 안 된다.** 인용 작성창에는 `···`에 `AI 레이블 추가`만 있고 시계 아이콘이 없다.

본문에 붙은 카드도 예약을 막지만, **카드 종류가 기준이다.** 2026-07-31 빈 작성창 대조 실험(Aside repl + claude-in-chrome 교차 확인, 두 도구 결과 동일):

| 작성창 상태 | `예약...` |
|---|---|
| 텍스트만 | 활성 |
| 텍스트 + 이미지 | 활성 |
| 텍스트 + **링크 미리보기 카드**(GitHub URL 등) | 활성 (`aria-disabled=null`) |
| 텍스트 + **Threads 인용카드**(share URL) | **비활성** (`aria-disabled="true"`) |

같은 작성창에서 링크 카드를 X로 떼고 share URL로 인용카드로 바꾸자 `예약...`이 활성→비활성으로 뒤집혔다. 즉 판정 기준은 "외부 게시물이 붙었느냐"가 아니라 **Threads 인용카드냐**다.

위치는 무관했다. 자답글 칸에 붙어도 같다(2026-07-31 02:20 실측): 자답글에 링크 카드 + 예약 배너 → `예약...`·`업데이트` 활성 / 자답글에 인용카드 + 예약 배너 → 둘 다 비활성.

예약 배너가 없는 새 글이면 인용카드가 있어도 `게시`는 활성이다(`aria-disabled=null` 확인). 배너를 떼면 바로 저장할 수 있다.

> **도구 차이가 아니었다 (2026-07-31 교차 검증 완료).** 위 표는 Aside repl과 claude-in-chrome **두 도구에서 같은 결과**가 나왔다. claude-in-chrome으로 다시 돌린 대조 실험에서도 링크 카드는 `aria-disabled=null`, 인용카드는 `aria-disabled="true"`로 갈렸다. 따라서 2026-07-29에 "링크 미리보기 카드도 예약을 막는다"고 적은 관측은 **틀린 기록**으로 판단한다. 그때 본 것이 실제로는 인용카드였을 가능성이 가장 크다. 기준은 카드 종류이고, 브라우저 도구와는 무관하다.

메뉴는 열리고 항목도 보이므로 **눈으로는 안 걸린다.** 회색으로 흐린 것뿐이라 클릭해도 아무 일이 없다. 판정은 DOM으로 한다:

```javascript
[...document.querySelectorAll('[role="menuitem"]')]
  .map(i => ({ t: i.innerText.trim(), dis: i.getAttribute('aria-disabled') }))
```

**카드를 뗄 수 있는지도 종류에 따라 갈린다** (2026-07-31, Aside repl):

- **링크 미리보기 카드는 뗄 수 있다.** 카드 우상단에 `삭제` X 버튼이 있고, 누르면 카드만 사라지고 URL 텍스트는 본문에 남는다.
- **인용카드는 작성창에서 못 뗀다.** hover해도 X가 없고(삭제·제거 계열 컨트롤이 DOM에 아예 없다), 본문 텍스트를 `Meta+a` → `Backspace`로 전부 비워 placeholder가 뜬 상태에서도 카드는 남았다. 없애려면 작성창을 닫고 새로 열어야 한다.

둘 다 Aside repl과 claude-in-chrome에서 같게 재현됐다.

그래서 **share URL을 치기 전에 결정한다:**

1. 예약이 필요하면 → 인용카드를 넣지 않는다. 원글은 계정명으로 언급하고, 발행 뒤 자답글에 링크를 단다.
2. 인용카드가 꼭 필요하면 → 예약을 포기하고 원하는 시각에 `게시`를 누른다(사람이 눌러도 되고, 예약 배너 없는 임시 저장본을 자동화가 열어 눌러도 된다).

### 인용카드는 share URL로만 만들어진다 (2026-07-31, Aside repl)

같은 게시물을 가리키는 URL이라도 형태에 따라 결과가 전혀 다르다.

| 작성창에 넣는 URL | 결과 |
|---|---|
| `https://www.threads.com/share/XXXXXXXX/` | **진짜 인용카드.** 원문 텍스트와 첨부 이미지까지 임베드되고, URL 텍스트는 카드로 바뀌며 사라진다. alt도 자동 생성된다(실측 973자) |
| `https://www.threads.com/@user/post/XXXX` | 프로필 사진만 크게 나오는 **일반 링크 미리보기**(`threads.com / 표시이름`). 인용 효과가 없다 |

share URL은 원글 `공유하기` → 링크 복사로 얻는다. 인용이 목적이면 긴 permalink를 쓰지 않는다.

### 한 칸에서 이미지와 인용카드는 양립 불가 (2026-07-31, Aside repl)

이미지 3장이 붙은 본문 칸에 share URL을 넣으면 **카드가 생기지 않고 URL이 파란 링크 텍스트로만 남는다.**

트리거 방식 문제가 아니다: URL 뒤 `Enter`를 눌러도 줄바꿈만 되고 9초 뒤까지 카드가 없었고, 20초를 더 기다려도 없었다. 같은 작성창에서 이미지를 X로 하나씩 제거하니 2장→없음, 1장→없음, **0장→즉시 카드 생성**(474x304, alt 973자, URL 텍스트 사라짐). 원인은 이미지다.

- 이미지와 인용을 같이 쓰려면 **칸을 나눈다.** 이미지는 본문에, 인용카드는 자답글 칸에 둔다.
- 카드가 안 생겨 남은 URL 텍스트를 지울 때는 캐럿을 URL 끝에 두고 URL 길이 + 빈 줄만큼 `Backspace`한다(실측 42회). DOM 직접 삭제는 쓰지 않는다(§11).

### 임시 저장은 인용카드를 보존하지 않는다 (2026-07-31, Aside repl)

카드를 붙인 뒤 `취소` → `임시 저장본 업데이트`로 저장하고 다시 열면 **텍스트와 이미지는 남지만 인용카드는 사라진다.**

그래서 인용카드가 필요한 글은 **게시 직전에 카드를 다시 붙인다.** 예약 배너를 뗀 텍스트·이미지 상태로 임시 저장해 두고, 발행 시점에 share URL을 넣어 카드를 만든 뒤 `게시`를 누르는 순서가 실제로 통했다.

편집 취소 확인창의 `업데이트 안 함`을 누르면 그 편집이 저장되지 않고 **원본 임시 저장본이 유지된다.** 실험용으로 카드를 붙였다가 원본을 되살릴 때 쓴다.

---

### 예약 글 수정 (2026-07-27 실측)

`임시 저장본`에서 예약 글을 열면 편집 모드이고, 여기서 **자답글 추가와 시각 변경이 둘 다 된다.**

- 자답글 추가: 맨 아래 `스레드에 추가` → 입력. 칸 번호가 `2/3` `3/3`으로 늘어나는 것으로 확인
- 시각 변경: `···` → `예약...` → 분 부분 삼중클릭 후 타이핑 → `완료`
- 마지막에 **`업데이트`**를 눌러야 반영된다. 누르지 않고 창을 닫으면 확인창이 뜨고, 거기서 `취소`하면 작성창이 유지된다

예약 시각 직전에도 수정이 먹힌다(발행 3분 전에 자답글 추가 + 10분 미루기 성공).

## 7. 예약한 글을 다시 찾기

**프로필에서 새 글 작성창을 열고 `임시 저장본` 버튼(작성창 우측 상단 문서 아이콘)을 누른다.** 예약 글이 그 목록에 있고, 클릭하면 편집 모드로 열린다. 하단 버튼이 `게시`가 아니라 **`업데이트`**면 편집 모드가 맞다.

여기에 **없는** 곳(전부 확인해본 헛수고):

- 왼쪽 사이드바 `더 보기` → 디자인/설정/좋아요/보관함/문제 신고/로그아웃뿐
- 프로필 우측 상단 `···` → `열로 추가`뿐
- 프로필 피드 → 예약 글은 표시되지 않음
- `https://www.threads.com/settings/scheduled_posts` → 404

작성창이 예약 글을 물고 있으면 다른 곳을 클릭할 때 `예약된 게시물을 업데이트하시겠어요?` 확인창이 뜬다. 더 고칠 예정이면 **`취소`**를 눌러 작성창을 유지한다. `업데이트`를 누르면 그 시점 내용으로 확정되고 창이 닫힌다.

## 8. API로는 예약이 안 된다

Threads 공식 API에 예약 발행 기능이 없다. API로 하려면 스케줄러(launchd 등)를 직접 만들어야 하므로, 일반 글은 웹의 `예약`을 쓰는 쪽이 확실하다.

## 9. 잘못 올렸을 때

**15분 안에 `수정`으로 복구한다** (점 3개 → 수정 → 완료). 삭제하지 않는다 — 삭제하면 그때까지 붙은 노출과 반응이 같이 사라지고, 같은 글을 다시 올려도 알고리즘이 처음부터 다시 시작한다.

### 답글 수정으로는 이미지를 추가할 수 없다 (2026-07-31, Aside repl)

이미 올린 답글의 `···` → `수정` 창에는 **미디어 첨부 버튼이 없고 `Cmd+V` 클립보드 붙여넣기도 무반응이다.** 텍스트만 고칠 수 있다.

이미지를 넣으려면 답글을 새로 올려야 한다. 안전한 순서는:

> **이미지 포함 답글을 먼저 게시 → 기존 답글 삭제 → (필요하면 새 답글 고정)**

새 답글을 먼저 올리므로 중간에 댓글이 비는 구간이 없다.

수정창을 `취소`하면 `수정 사항을 삭제하시겠어요?` 확인창이 뜬다. 거기서 `삭제`를 눌러도 **원 답글은 그대로 유지되고 수정 내용만 버려진다.**

## 10. 답글 고정 — 교체할 때 확인창이 뜬다 (2026-07-31, Aside repl)

답글 고정은 답글의 `···` → `답글 고정`이다. 고정이 처음이면(기존 고정 없음) 확인창 없이 바로 적용된다.

**이미 고정된 답글이 있으면 확인창이 뜬다:**

> `현재 고정된 메시지를 바꾸시겠어요? / 한 번에 하나의 답글만 스레드에 고정할 수 있습니다.`

이 창의 `확인`을 누르지 않으면 **고정이 조용히 무효화된다.** 오류 메시지가 없고 메뉴만 닫히므로, `고정됨` 배지가 없는 것을 보고 "고정 기능이 안 된다"고 오판하기 쉽다. 실제로 이 확인창을 놓쳐 **4회 연속 실패**했다 — DOM click, 좌표 클릭, pointer 이벤트 시퀀스, locator ref 클릭 모두 같은 결과였다. 클릭 방식이 문제가 아니었다.

절차:

1. `···` → `답글 고정` 클릭
2. **`div[role="dialog"]` 존재를 확인**한다. 있으면 `확인`을 누른다
3. 그 뒤 새로고침 한 번으로 `고정됨` 배지를 확인한다

## 11. 작성창 조작 함정 (2026-07-31, Aside repl)

브라우저 자동화로 작성창을 다룰 때 반복해서 값을 치른 것들이다.

**캐럿은 클릭으로 끝에 가지 않는다.** 칸을 클릭하거나 `Meta+ArrowDown`을 눌러도 캐럿이 직전 편집 위치(문단 중간)로 가는 일이 반복돼 URL이 글 중간에 박혔다. 확실한 방법은 Range로 끝으로 보내는 것이다:

```javascript
const r = document.createRange();
r.selectNodeContents(el);
r.collapse(false);              // 끝으로
const s = getSelection(); s.removeAllRanges(); s.addRange(r);
```

**본문 칸이 snapshot에 안 잡히면 스크롤을 의심한다.** 작성창을 열면 스크롤이 아래쪽에 있어 본문 칸이 트리에 안 나오는 경우가 있다. 스크롤 컨테이너(`generic [scrollable]`)의 `scrollTop = 0`으로 올린 뒤 다시 snapshot을 찍으면 모든 칸 ref가 나온다.

**해시태그를 넣으려고 다시 클릭하지 않는다.** 본문 입력 후 재클릭하면 캐럿이 중간으로 튀어 문장 사이에 태그가 박힌다. 본문과 해시태그는 한 번의 `type`으로 이어서 넣는다.

**DOM 직접 삭제는 쓰지 않는다.** `execCommand('delete')` + TreeWalker/Range 조합은 Lexical 에디터에서 줄 순서를 뒤섞을 수 있다. 링크는 텍스트 노드로 잡히지 않아 TreeWalker 검색 자체가 실패한다. 칸을 비우고 다시 타이핑하는 편이 확실하다.

### Aside repl로 조작할 때

- `attachBrowserTab`이 `No open browser tab found`로 실패한 이력이 있다. `openTab()`으로 새 탭을 여는 편이 확실했다.
- `page.evaluate`가 잘못된 프레임을 잡아 `document.querySelectorAll('div[role="dialog"]')`가 0을 반환한 일이 있다. **ref 기반 조작과 `locator.evaluate`를 우선한다.**
- 확장 작성창은 `role="dialog"`가 아니라 **`role="menu"`**로 잡힌다(2026-07-31 확인). `dialog`로만 찾으면 작성창을 못 찾는다. 확인창은 `dialog`다.
- 액션마다 ref가 무효화되니 새 snapshot을 찍는다. `page.waitForTimeout`은 없고 `sleep(ms)`를 쓴다. REPL 스코프가 유지되므로 변수명을 매번 새로 쓴다.
- **게시 직후 `document.body.innerText` 검색이 렌더링 지연으로 방금 올린 내용을 못 찾는 일이 자주 있다.** 스크린샷이나 snapshot으로 재확인한다. 텍스트 검색 실패를 "게시 안 됨"으로 오판하지 않는다.
- 좌표 클릭은 스크린샷 좌표와 뷰포트 좌표가 달라(실측 배율 약 0.71/0.72) 엉뚱한 링크를 눌러 페이지가 이동하는 사고가 났다. 가능하면 ref 클릭을 쓴다.

## 12. 되돌릴 수 없는 클릭 전에는 정체를 확인한다

`find`가 돌려주는 설명은 **접근성 트리와 주변 텍스트에서 추론한 것**이지 확인된 사실이 아니다. 특히 `button "(no name)"`은 그 요소에 이름이 없다는 뜻이라, 붙은 설명일수록 근거가 약하다.

2026-07-29에 "링크 카드의 삭제 버튼"이라고 설명된 `(no name)` 버튼을 눌렀더니 **`게시`였다.** 예약하려던 글이 그 자리에서 발행됐다.

`게시`·`삭제`·`저장 안 함`처럼 되돌릴 수 없는 자리에서는 클릭 전에 확인한다:

```javascript
const el = /* find가 준 ref의 요소 */;
JSON.stringify({
  text: el.innerText,
  aria: el.getAttribute('aria-label'),
  rect: el.getBoundingClientRect(),                    // 어디에 있는 버튼인가
  inDialog: !!el.closest('div[role="dialog"]')
})
```

**위치만 봐도 대개 갈린다.** 카드를 떼는 버튼이 작성창 맨 아래 `게시` 자리에 있을 리 없다.

### 작성창이 사라지면 발행부터 의심한다

**닫힘과 발행은 화면상 구분이 안 된다.** 사라진 직후 **프로필 피드 최상단**을 먼저 확인한다. 임시 저장본을 뒤지는 건 그다음이다.

이 순서를 뒤집으면 "초안이 날아갔다"고 오판하고 같은 글을 다시 쓰게 된다 — 중복 발행 직전까지 간 적이 있다.

**사용자가 "게시된 것 같다"고 말하면 그 말이 내 화면 판단보다 우선한다.** 즉시 피드를 확인하고, 확인될 때까지 다음 입력을 하지 않는다.

## 입력 3원칙 (매번 적용)

1. **모든 편집 칸은 `.`으로 시작**해 타이핑하고, 끝나면 맨 앞 1글자를 지운다 → 앞 글자 잘림 방어
2. **해시태그는 `#태그 ` 단위로 뒤 공백까지** 하나씩 → 토큰 병합 방어
3. **팝업은 X 버튼으로 닫는다** → Escape는 작성창까지 닫는다

## 발행 전 점검

- [ ] 확장 창에서 썼는가 (인라인 Enter로 반쪽만 올라가지 않았는가)
- [ ] 전문을 `innerText`로 검증했는가 (한글 오타, **잘린 앞 글자**, **뭉친 해시태그**)
- [ ] 각 칸 글자 수가 초안과 **정확히 일치**하는가 (줄바꿈 제외)
- [ ] 자답글을 `스레드에 추가`로 묶었는가 (칸 번호 `n/N`로 확인)
- [ ] 사진마다 alt를 넣었는가
- [ ] 다중 이미지의 세로 비율이 비슷한가
- [ ] 해시태그가 본문 마지막에 단독으로 있는가 (자답글에는 0개)
- [ ] 예약이라면 배너와 `예약` 버튼을 눈으로 확인했는가
- [ ] 예약이라면 인용카드가 안 붙어 있는가 (붙으면 `예약...`이 비활성) — 카드가 있다면 `예약...` 상태를 DOM으로 확인
- [ ] 인용카드가 필요한 글인가 (임시 저장은 카드를 보존하지 않으니 게시 직전에 다시 붙였는가)
- [ ] 인용카드를 붙일 칸에 이미지가 없는가 (한 칸에서 양립 불가)
- [ ] `(no name)` 버튼을 누르기 전에 정체를 DOM으로 확인했는가
- [ ] 답글 고정을 교체했다면 확인창의 `확인`을 눌렀는가 (`고정됨` 배지로 검증)

줄바꿈·문단 규칙은 `threads-linebreak` 스킬을 쓴다.
