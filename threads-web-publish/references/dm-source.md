# DM을 글 소재로 쓰기

Threads DM에서 발화자·입력 경로·첨부를 확인하고 동의 범위 안에서 초안을 만들 때 읽는다.
Aside 앱과 Threads 로그인이 필요하다. `aside guide`를 읽고 `aside exec`으로 위임한다.
좌표·입력칸·첨부를 직접 확인할 때만 `aside guide repl`을 읽고 REPL을 사용한다.
사용자가 지정한 대화·범위를 [위임 양식](aside-setup.md)에 넣고 읽기 전용 여부를 명시한다.
소재 확인이나 글 작성 요청만으로 DM을 보내지 않는다. 전송이 명시적으로 허용된 경우에만 아래 전송 절차를 쓴다.
작업 중 새로고침하지 않으며 관찰 결과와 행동 주체를 구분한다. 모르는 정보는 미확인으로 남긴다.

## 게재 동의부터 확인

초안을 쓰기 전에 상대의 게재·인용 동의를 확인한다.
인용할 발언·첨부의 범위와 실명·계정 공개 여부를 함께 확인하며, 익명 처리 여부도 정한다.
이미 제공된 동의가 이 범위에 해당하면 다시 요구하지 않는다.
동의가 없으면 필요한 확인 내용을 사용자에게 제시하고 비공개 대화를 임의로 인용하지 않는다.
상대가 내용이나 작업물을 계속 수정 중이면 발행 직전 현재 상태를 재확인한다.

## 전문과 발화자 확인

1. 요청한 대화 범위의 앞뒤 맥락을 읽는다. 오래된 메시지가 필요하면 위로 스크롤해 로딩된 내용을 시간순으로 이어 본다.
2. 접근성 트리 순서만으로 발화자를 나누지 않는다. 트리는 좌우 말풍선을 한 줄의 목록으로 펼친다.
3. 대화 그리드의 가로 중심 `left + width / 2`와 각 말풍선의 중심 x좌표를 비교한다.
4. 화면에서 오른쪽이 나, 왼쪽이 상대인 배치를 확인한 뒤 발화자를 붙인다. UI 방향이 다르거나 좌표가 불분명하면 추정하지 않는다.
5. DOM으로 읽을 때 부모가 합친 문장을 중복 수집하지 않도록 말풍선의 말단 텍스트를 읽고, 텍스트와 세로 좌표를 함께 확인한다.
6. “발화자 / 전문 / 시각 / 근거”를 연결해 기록한다. 보이는 메시지를 내가 보냈다고 단정하지 않는다.

## 입력 경로는 사용자에게 확정

STT(음성 전사) 출력과 키보드 직접 입력은 사용자에게 확인해 구분한다.
문장부호, 오탈자, 외국 문자, 기술 용어의 정확도는 후보를 좁히는 단서일 뿐 확정 규칙이 아니다.

1. 구분이 필요한 발언을 원문 그대로 제시한다.
2. 사용자에게 어떤 발언이 STT 출력이고 어떤 발언이 직접 입력인지 확인한다.
3. 사용자의 정정을 우선하며 이미 확정한 분류를 같은 단서로 다시 뒤집지 않는다.
4. 확정되지 않은 것은 미확인으로 표시한다. 글에서 STT 출력을 사람의 판단이나 발언 의도로 바꾸어 인용하지 않는다.

## 첨부 확인과 저장

대화 안의 `img[alt="메시지 첨부 파일"]`를 찾아 첨부 후보를 확인한다.
링크 미리보기의 빈 alt와 구분하고 말풍선 위치로 첨부 발화자를 연결한다.
이 alt 값만으로 누가 보냈는지 확정하지 않는다.

현재 DOM에서 확인한 `currentSrc`, `naturalWidth`·`naturalHeight`를 기록하고 원본을 읽는다.
REPL의 `fetch()`는 화면에서 확인한 같은 출처 또는 신뢰하는 직접 다운로드 URL의 GET에만 쓴다.
세션 안의 `./artifacts/`에 `await fs.writeFile()`로 저장하고 호출 측 셸에서 가져온다.
`fs.writeFileSync`나 세션 바깥 경로 직접 쓰기를 사용하지 않는다.
게시에 쓸 첨부와 alt 문안은 게재 동의 범위 및 실제 이미지 내용에 맞춰 준비한다.

## 허용된 DM 전송

1. 대상 대화와 전송할 정본을 확인한다. 메시지 요청함의 `수락`이 필요한 경우 실제 요청된 대화인지 확인하고 수락한다.
2. 작성창을 클릭하고 `activeElement`가 입력칸인지 확인한다.
3. `await sleep(1000)`으로 1초 기다린다.
4. 한글·숫자·공백·문장부호가 포함된 정본을 청크로 나누어 타이핑한다. 줄 경계는 `Shift+Enter`로 넣고, 청크마다 `innerText`를 현재까지의 정본과 문자 단위로 대조한다.
5. 전문을 다시 대조한 뒤 사용자가 허용한 메시지만 Enter로 전송한다. `Meta+Enter`를 전송 키로 가정하지 않는다.
6. 새 snapshot과 화면에서 말풍선 전문을 확인한다. 클릭 시도만으로 전송 완료라고 보고하지 않는다.

입력이 손상됐으면 작성창에 포커스를 두고 `Meta+A → Delete`로 비워 다시 입력한다.
이미 보낸 내 메시지를 고쳐야 하면 hover 후 `더 보기 → 수정`으로 들어간다.
두 곳 이상 치환할 때는 전체를 다시 타이핑하고 저장 후 `수정됨` 배지와 전문을 확인한다.
전송 취소는 요청된 경우에만 수행한다.

## 소재 확정 점검

- [ ] 게재·인용·첨부 공개·실명 범위의 동의가 있는가.
- [ ] 요청한 범위의 전문을 읽고 좌우 좌표로 발화자를 확인했는가.
- [ ] STT/키보드 분류를 사용자에게 확인받았는가.
- [ ] 첨부 alt·원본과 발화자 연결을 확인했는가.
- [ ] 발행 직전 상태와 표현의 시점을 현재 KST에 맞춰 확인했는가.
- [ ] DM 전송 요청이 있다면 클릭·1초 대기·청크 입력·문자 대조를 거쳤는가.

확정된 사실과 미확인 사항을 나누어 초안에 반영한다.
게시까지 요청받았다면 [발행 스킬](../SKILL.md)의 초안 확보·발행 전 점검·+16분 검증 절차로 이어간다.
