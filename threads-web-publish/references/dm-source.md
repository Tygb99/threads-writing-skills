# DM을 소재로 쓸 때



`threads-web-publish` 상세 참조. Threads DM 대화를 글 소재로 정리할 때 읽는다.



---

## 1. 발화자와 입력 경로를 먼저 가른다 (2026-07-31, Aside repl)

DM 대화를 글 소재로 삼으려면 대화를 읽는 것만으로는 부족하다. **누가 말했는지, 어떻게 입력했는지**를 먼저 확정해야 한다. 이걸 건너뛰어 같은 대화에서 판단을 네 번 뒤집었다.

### 접근성 트리는 좌우를 알려주지 않는다

`snapshot()`이 뽑는 트리는 말풍선을 **위에서 아래로 한 줄로 펼친다.** 내 메시지와 상대 메시지가 구분 없이 섞여 나오고, 프로필 이미지 링크가 상대 쪽에만 붙는 것도 일정하지 않다. 그대로 읽으면 상대 발언을 내 발언으로, 내 발언을 상대 발언으로 읽는다.

실제로 `저 이제 병원가야`를 상대 발언으로 읽었고, 상대가 자기 사양을 물은 것을 내가 답한 것으로 뒤집어 읽었다. 그 상태로 DM을 보내 이미 답한 내용을 다시 묻는 사고가 났다.

**말풍선 중심 x좌표로 가른다.** 그리드 가로 중앙을 기준으로 오른쪽이 나, 왼쪽이 상대다:

```javascript
const grid = document.querySelector('[role="grid"]');
const mid = grid.getBoundingClientRect().left + grid.getBoundingClientRect().width / 2;
const out = []; const seen = new Set();
grid.querySelectorAll('div,span').forEach(el => {
  const t = (el.innerText || '').trim();
  if (!t || t.length < 2) return;
  if (el.querySelector('div,span')) return;      // leaf만
  const r = el.getBoundingClientRect();
  if (r.width === 0) return;
  const k = t + '|' + Math.round(r.top);
  if (seen.has(k)) return; seen.add(k);
  out.push({ top: Math.round(r.top), side: (r.left + r.width/2) > mid ? 'ME' : 'THEM', text: t });
});
out.sort((a,b) => a.top - b.top);
```

`leaf만` 필터가 중요하다. 없으면 부모 컨테이너가 자식 텍스트를 합쳐 뱉어 같은 문장이 여러 번 잡힌다.

### 음성 입력과 키보드 입력을 가른다 — 단, 사용자에게 물어서 확정한다

STT 앱으로 말해서 보낸 메시지와 키보드로 직접 친 메시지는 성격이 전혀 다르다. 전자는 앱의 출력이고 후자는 사람의 판단이다. 글에서 이 둘을 섞으면 서사가 틀어진다.

**그런데 이 구분을 자동으로 판정할 수 있는 일반 규칙은 없다.** 입력 습관은 사람마다 다르고, 같은 사람도 상황에 따라 바뀐다. 키보드로 칠 때 마침표를 찍는 사람도 있고 안 찍는 사람도 있다. 그러니 아래는 **후보를 좁히는 단서**로만 쓰고, 판정은 반드시 사용자에게 확인받는다.

#### 단서 (판정이 아니다)

| 관찰 | 그럴 가능성 |
|---|---|
| 문장 끝에 `.` `?` 가 일관되게 붙음 | STT 전사 — 엔진이 문장부호를 자동으로 넣는다 |
| 한 문장 안에서 어절이 뭉개짐 (`좋좋겠어 요`) | 어느 쪽이든 가능 — 입력 오류의 흔적 |
| **비라틴 외국 문자**(힌디·태국·아랍 등) | STT 오인식 — 한국어 부호가 붙을 수 없어 부호 유무로 못 가른다 |
| 기술 용어·수치·경로가 정확히 적힘 | 키보드 직접 입력일 가능성 |

2026-07-31 세션에서는 이 계정 기준으로 "부호 있음 = STT, 부호 없는 한글·영숫자 = 키보드"가 대체로 맞았지만, **그건 이 사용자의 그날 습관이었을 뿐이다.** 규칙으로 굳히면 안 된다.

#### 확인 절차

1. 단서로 두 묶음을 만든다.
2. **사용자에게 목록을 보여주고 확정받는다.** "이쪽이 직접 치신 것 맞나요?"
3. 사용자가 정정하면 그 말이 단서보다 우선한다. 되묻지 않는다.

실제로 이 절차를 건너뛰어 세 번 틀렸다. 힌디 문자를 "부호가 없으니 직접 입력"으로 분류했고, 사용자가 `인ㅗ어 힌디어 제외`라고 정정한 뒤에야 STT 출력임이 확정됐다. 그 직전에는 좌우 정렬을 잘못 읽어 발화자를 뒤집었다.

판별이 끝나면 키보드 입력만 따로 모아본다. 대개 그쪽에 사양 보고, 원인 가설, 요청사항 같은 판단이 모여 있어 글의 중심이 된다.

### 첨부 이미지는 `alt`로 걸러 원본을 받는다

내가 보낸 첨부는 `alt="메시지 첨부 파일"`이고, 상대가 보낸 링크 미리보기는 `alt=""`다. 링크 카드를 첨부 사진으로 착각하지 않도록 alt로 먼저 가른다.

```javascript
[...document.querySelectorAll('[role="grid"] img')]
  .filter(i => i.alt === '메시지 첨부 파일')
  .map(i => ({ src: i.currentSrc, dim: `${i.naturalWidth}x${i.naturalHeight}` }))
```

`fetch(src)`로 원본을 받을 수 있다(쿠키가 붙는다). 단 **Aside repl의 `fs`는 세션 루트 밖으로 못 쓴다** — `./artifacts/`에 저장하고 셸로 옮긴다. `fs.writeFileSync`도 없다. `await fs.writeFile(path, buf)`를 쓴다.

### DM 작성창은 클릭 직후 타이핑하면 한글 외 문자를 삼킨다 (2026-08-15, claude-in-chrome)

`left_click` 바로 뒤에 `type`을 이어 붙이면 공백·숫자·마침표·따옴표·`shift+Return` 줄바꿈이 전부 유실되고 한글만 남는다 — 350자가 242자로 뭉친 실측. 같은 절차라도 클릭 후 1초 대기를 넣으면 정상이다(IME 초기화로 추정). **DM 창에서는 클릭 → 1초 대기 → 청크 단위 타이핑 → 청크마다 `innerText` 검증**으로 간다. 복구는 작성창 클릭 후 `cmd+a` → `Delete`(길이 1이면 비어 있는 것). 전송은 `Return`(`cmd+Return` 아님). 첫 메시지가 요청함에 있으면 `수락`을 먼저 눌러야 입력창이 뜬다.

### 보낸 뒤에도 고칠 수 있다

내 메시지에 hover하면 `더 보기` 버튼이 뜨고 `수정` / `복사` / `전송 취소`가 있다. **`수정`이 `전송 취소`보다 낫다** — 취소는 대화 흐름에 구멍을 남긴다.

단 수정창에서 **여러 군데를 `insertText`로 연속 치환하면 Lexical이 조각들을 첫 줄에 몰아넣는다.** 실제로 `어제`→`오늘` 4곳을 바꾸려다 문장이 뒤엉켰다. 두 곳 이상 고칠 때는 `Meta+a` → `Backspace`로 비우고 전체를 다시 타이핑한다.

수정하면 말풍선에 `수정됨` 배지가 붙는다. 이걸로 반영을 확인한다.

### 게재 동의는 글을 쓰기 전에 받는다

상대의 미완성 상태나 사과가 대화에 섞여 있으면 그대로 인용하기 전에 물어본다. 실명·계정 공개 여부와 인용 범위를 함께 묻고, 부담되면 익명으로 쓰겠다는 선택지를 같이 준다. 2026-07-31 사례에서는 `적나라하게 적어주셔도 되세요`, `모든 부분 인용하셔도 되세요`라는 승낙을 받고 나서 초안을 썼다.

### DM 소재 점검

- [ ] 좌우 x좌표로 발화자를 갈랐는가 (트리 순서만 믿지 않았는가)
- [ ] STT/키보드 입력 후보를 단서로 좁혔는가
- [ ] **그 분류를 사용자에게 확인받았는가** (문장부호는 사람·상황마다 달라 단서일 뿐이다)
- [ ] 키보드 직접 입력만 따로 모아 글의 중심을 정했는가
- [ ] 첨부 이미지를 `alt`로 걸러 원본을 받았는가
- [ ] 스크롤을 끝까지 올려 옛 메시지까지 읽었는가 (`scrollTop = 0` 반복)
- [ ] 초안을 쓰기 전에 게재·인용 동의를 받았는가
- [ ] 상대가 지금도 고치는 중이면 발행 직전에 상태를 재확인했는가
- [ ] DM을 보낼 때 클릭 → 1초 대기 → 청크 타이핑 → `innerText` 검증을 지켰는가
