# 예약 발행과 인용카드



`threads-web-publish` 상세 참조. 예약을 걸거나 인용카드를 붙일 때 읽는다.



---

## 1. 예약 발행

작성창 우측 상단 `···` → **`예약...`** → 달력에서 날짜 클릭 → 하단 시간 입력(`15 : 00` 형식, 시·분 각각 삼중클릭 후 타이핑) → `완료`.

설정되면 상단에 `수요일 오후 7:00 GMT+9에 게시 예정` 배너가 뜨고, 하단 버튼이 `게시` → **`예약`**으로 바뀐다. `게시물 옵션`은 답글 권한 설정이라 예약과 무관하다.

### ⚠️ 시각 입력칸에 키보드 타이핑이 안 먹는다 — `fill()`을 쓴다 (2026-08-27, Aside repl)

시·분 칸은 `input[placeholder="hh"]` / `input[placeholder="mm"]`인데 **삼중클릭 후 타이핑이 실패한다.**

실측: `hh`를 삼중클릭하고 `18`을 타이핑하니 **`08`**이 됐다(마지막 자리만 먹었다). 이어서 `1` → `8`을 따로 눌러도 값이 **아예 안 바뀌었다**(`08` 고정, 포커스는 `hh`로 정상). 컨트롤드 인풋이라 키 이벤트가 상태에 반영되지 않는다.

> **Playwright `locator.fill()`로 넣는다.** `await page.locator('input[placeholder="hh"]').fill('18')` → 한 번에 `18`이 정확히 들어갔고 `mm`도 `fill('04')`로 성공했다.

- 시각은 **24시간 표기**다. 오후 6시는 `18`이지 `6`이 아니다. AM/PM 토글이 없다.
- `08`처럼 조용히 틀린 값이 들어가면 **10시간 어긋난 시각에 발행된다.** 넣은 뒤 반드시 두 칸 `value`를 다시 읽어 확인한다.
- `완료`를 누른 뒤 배너 문자열(`오늘 오후 6:04 GMT+9에 게시 예정`)로 한 번 더 대조한다. 배너는 12시간 표기라 24시간 입력값과 눈으로 맞춰봐야 한다.

### alt를 재확인하려고 첨부 옵션을 다시 열 때 작성창이 닫힐 수 있다 (2026-08-27, Aside repl)

alt 저장을 검증하려고 이미지 hover → `첨부 파일 옵션`을 **locator로 다시 클릭**했더니 클릭이 작성창 바깥(오버레이)에 떨어져 **`임시 저장하시겠어요?` 확인창이 두 번 떴다.** 7칸을 다 채우고 사진·alt까지 넣은 뒤였다.

- 확인창이 뜨면 **`취소`**다(절대 규칙 4). `저장 안 함`을 눌렀으면 전부 날아갔다.
- 닫은 직후 **전 칸을 다시 문자 단위로 대조**해 유실이 없는지 확인한다(이 사례에서는 7칸 전부 무사했다).
- 재클릭은 좌표나 stale locator 대신 **새로 뜬 snapshot의 ref**로 한다. ref 기반으로 바꾸니 메뉴가 정상적으로 열렸다.
- 애초에 **alt는 DOM에서 읽는 쪽이 안전하다.** `img.alt` 속성을 직접 읽으면 메뉴를 열 필요가 없다: `d.querySelector('img[src^="blob:"]').alt` — 저장된 alt가 그대로 들어 있고, 길이·문자 대조까지 클릭 없이 끝난다.

### 예약을 막는 건 인용카드다. 링크 카드는 막지 않는다

**인용글은 예약이 안 된다.** 인용 작성창에는 `···`에 `AI 레이블 추가`만 있고 시계 아이콘이 없다.

본문에 붙은 카드도 예약을 막지만, **카드 종류가 기준이다.** 2026-07-31 빈 작성창 대조 실험(Aside repl + claude-in-chrome 교차 확인, 두 도구 결과 동일):

| 작성창 상태 | `예약...` |
|---|---|
| 텍스트만 | 활성 |
| 텍스트 + 이미지 | 활성 |
| 텍스트 + **링크 미리보기 카드**(GitHub URL 등) | 활성 (`aria-disabled=null`) |
| 텍스트 + **Threads 인용카드**(share URL) | **비활성** (`aria-disabled="true"`) |

같은 작성창에서 링크 카드를 X로 떼고 share URL로 인용카드로 바꾸자 `예약...`이 활성→비활성으로 뒤집혔다. 즉 판정 기준은 "외부 게시물이 붙었느냐"가 아니라 **Threads 인용카드냐**다.

위치는 무관했다. 자답글 칸에 붙어도 같다(2026-07-31 02:20 실측): 자답글에 링크 카드 + 예약 배너 → `예약...`·`업데이트` 활성 / 자답글에 인용카드 + 예약 배너 → 둘 다 비활성.

예약 배너가 없는 새 글이면 인용카드가 있어도 `게시`는 활성이다(`aria-disabled=null` 확인). 배너를 떼면 바로 저장할 수 있다.

> **도구 차이가 아니었다 (2026-07-31 교차 검증 완료).** 위 표는 Aside repl과 claude-in-chrome **두 도구에서 같은 결과**가 나왔다. claude-in-chrome으로 다시 돌린 대조 실험에서도 링크 카드는 `aria-disabled=null`, 인용카드는 `aria-disabled="true"`로 갈렸다. 따라서 2026-07-29에 "링크 미리보기 카드도 예약을 막는다"고 적은 관측은 **틀린 기록**으로 판단한다. 그때 본 것이 실제로는 인용카드였을 가능성이 가장 크다. 기준은 카드 종류이고, 브라우저 도구와는 무관하다.

메뉴는 열리고 항목도 보이므로 **눈으로는 안 걸린다.** 회색으로 흐린 것뿐이라 클릭해도 아무 일이 없다. 판정은 DOM으로 한다:

```javascript
[...document.querySelectorAll('[role="menuitem"]')]
  .map(i => ({ t: i.innerText.trim(), dis: i.getAttribute('aria-disabled') }))
```

**카드를 뗄 수 있는지도 종류에 따라 갈린다** (2026-07-31, Aside repl):

- **링크 미리보기 카드는 뗄 수 있다.** 카드 우상단에 `삭제` X 버튼이 있고, 누르면 카드만 사라지고 URL 텍스트는 본문에 남는다.
- **인용카드는 작성창에서 못 뗀다.** hover해도 X가 없고(삭제·제거 계열 컨트롤이 DOM에 아예 없다), 본문 텍스트를 `Meta+a` → `Backspace`로 전부 비워 placeholder가 뜬 상태에서도 카드는 남았다. 없애려면 작성창을 닫고 새로 열어야 한다.

둘 다 Aside repl과 claude-in-chrome에서 같게 재현됐다.

그래서 **share URL을 치기 전에 결정한다:**

1. 예약이 필요하면 → 인용카드를 넣지 않는다. 원글은 계정명으로 언급하고, 발행 뒤 자답글에 링크를 단다.
2. 인용카드가 꼭 필요하면 → 예약을 포기하고 원하는 시각에 `게시`를 누른다(사람이 눌러도 되고, 예약 배너 없는 임시 저장본을 자동화가 열어 눌러도 된다).

### 인용카드는 share URL로만 만들어진다 (2026-07-31, Aside repl)

같은 게시물을 가리키는 URL이라도 형태에 따라 결과가 전혀 다르다.

| 작성창에 넣는 URL | 결과 |
|---|---|
| `https://www.threads.com/share/XXXXXXXX/` | **진짜 인용카드.** 원문 텍스트와 첨부 이미지까지 임베드되고, URL 텍스트는 카드로 바뀌며 사라진다. alt도 자동 생성된다(실측 973자) |
| `https://www.threads.com/@user/post/XXXX` | 프로필 사진만 크게 나오는 **일반 링크 미리보기**(`threads.com / 표시이름`). 인용 효과가 없다 |

share URL은 원글 `공유하기` → 링크 복사로 얻는다. 인용이 목적이면 긴 permalink를 쓰지 않는다.

**2026-08-28 재확인 (Aside repl).** permalink를 자답글 칸에 타이핑하니 6초 뒤 `threads.com / 표시이름`(프로필 사진 + 삭제 X 버튼)짜리 일반 링크 미리보기만 붙었다. 위 표 그대로다. 이때 잠시 다른 탭에 다녀온 사이 카드가 진짜 인용카드로 바뀌어 있어서 "Threads가 알아서 전환한다"고 보고했는데 **틀렸다 — 사용자가 그 사이에 링크를 share URL로 직접 바꾼 것이었다**(사용자 확인). 절대 규칙 5번 "본 것으로 원인을 지어내지 마라, 사용자도 같은 브라우저를 조작한다"의 교과서적 재발이다. **permalink는 기다려도 인용카드가 되지 않는다.**

두 카드는 DOM으로 즉시 갈린다:

| | 링크 미리보기 | 인용카드 |
|---|---|---|
| 카드 안 삭제(X) 버튼 | 있다 | **없다**(0개) |
| 카드 텍스트 | `threads.com` + 표시이름 | **원글 본문 전문** + `n/N` + 원글 반응수 |
| 편집칸 `innerText`의 URL 문자열 | 남는다 | **사라진다**(카드가 흡수) |

### 클립보드 읽기가 막힌 환경에서 share URL 값을 확인하는 법 (2026-08-28, Aside repl)

`링크 복사`는 실클릭이면 정상 동작하지만, **Aside 샌드박스에서는 복사된 값을 못 읽는다** — `navigator.clipboard.readText()`가 `NotAllowedError: blocked because of a permissions policy`로 막히고, Playwright `page.context()`도 REPL에 노출되지 않아 `grantPermissions`로 뚫을 수 없다.

우회는 **붙여넣기**다. 값만 보면 되므로 중립 페이지의 입력칸에 붙여 읽는다:

1. `openTab('https://www.google.com')` → 검색칸 클릭
2. `page.keyboard.press('Meta+v')` — CDP 키 이벤트로도 네이티브 붙여넣기가 동작한다(실측)
3. `input/textarea.value`를 읽어 URL 확보 → 읽고 나면 `fill('')`로 지우고 탭을 닫는다

작성 중인 모달 탭에 직접 붙여넣어 확인하지 말 것. 값이 틀렸을 때 되돌리는 비용이 크다.

체인 안의 자답글(`n/10` 같은 연재글)도 **전송 시트 하단 `링크 복사`**로 받으면 부모가 아니라 그 글 자체를 가리킨다(실측: `5/ Second Voice` → `https://www.threads.com/share/E3E-C_D8G/`).

### 답글(댓글)도 인용카드가 된다 — 단, 전송 시트에서 복사해야 (2026-08-13 실측, 사용자 검증)

답글을 인용하려다 **부모 글이 임베드되는** 함정이 있다. 같은 "링크 복사"인데 어느 UI에서 받느냐로 결과가 갈린다:

| 경로 | 받은 share URL | 임베드 결과 |
|---|---|---|
| 답글 공유 아이콘 → **드롭다운 메뉴**의 "링크 복사" | (실측 D16EGodqm) | **부모 글** — 답글 인용 실패 |
| 답글 비행기(공유하기) → **전송 시트("받는 사람" 다이얼로그) 하단**의 "링크 복사" | (실측 GfNi1BXQx) | **답글 자체** ✓ |

- 전송 시트 하단 줄: Instagram 스토리 · **링크 복사** · 이미지로 복사 · 퍼가기 코드.
- 브라우저 자동화에서 이 링크 복사는 **실클릭이어야** 클립보드에 써진다(JS `.click()`은 클립보드 권한이 없어 무반응).
- 검증: 작성창에 붙여 4초쯤 기다려 임베드된 카드의 **본문 텍스트가 답글 내용인지** 확인 후 진행(부모 본문이면 잘못된 URL).

### 한 칸에서 이미지와 인용카드는 양립 불가 (2026-07-31, Aside repl)

이미지 3장이 붙은 본문 칸에 share URL을 넣으면 **카드가 생기지 않고 URL이 파란 링크 텍스트로만 남는다.**

트리거 방식 문제가 아니다: URL 뒤 `Enter`를 눌러도 줄바꿈만 되고 9초 뒤까지 카드가 없었고, 20초를 더 기다려도 없었다. 같은 작성창에서 이미지를 X로 하나씩 제거하니 2장→없음, 1장→없음, **0장→즉시 카드 생성**(474x304, alt 973자, URL 텍스트 사라짐). 원인은 이미지다.

- 이미지와 인용을 같이 쓰려면 **칸을 나눈다.** 이미지는 본문에, 인용카드는 자답글 칸에 둔다.
- 카드가 안 생겨 남은 URL 텍스트를 지울 때는 캐럿을 URL 끝에 두고 URL 길이 + 빈 줄만큼 `Backspace`한다(실측 42회). DOM 직접 삭제는 쓰지 않는다(`composing.md` §6).

### 임시 저장은 인용카드를 보존하지 않는다 (2026-07-31, Aside repl)

카드를 붙인 뒤 `취소` → `임시 저장본 업데이트`로 저장하고 다시 열면 **텍스트와 이미지는 남지만 인용카드는 사라진다.**

그래서 인용카드가 필요한 글은 **게시 직전에 카드를 다시 붙인다.** 예약 배너를 뗀 텍스트·이미지 상태로 임시 저장해 두고, 발행 시점에 share URL을 넣어 카드를 만든 뒤 `게시`를 누르는 순서가 실제로 통했다.

편집 취소 확인창의 `업데이트 안 함`을 누르면 그 편집이 저장되지 않고 **원본 임시 저장본이 유지된다.** 실험용으로 카드를 붙였다가 원본을 되살릴 때 쓴다.

### 링크 카드는 반대로, 뗀 것이 되살아난다 (2026-08-08, claude-in-chrome)

인용카드가 저장에서 사라지는 것과 정확히 반대다. **본문·자답글에 URL 텍스트가 남아 있으면, 예약 글을 편집 모드로 다시 열 때마다 링크 미리보기 카드(og 이미지)가 자동으로 다시 생성된다.** X로 뗀 상태로 `예약`/`업데이트`를 눌러 저장해도 소용없다 — 다음에 열면 또 붙어 있다.

실측 (오전 10:00 예약 글, 유튜브 + 오픈카카오 링크 각 1개):

1. 작성 시 유튜브 카드를 X로 떼고 `예약` 저장
2. 문구 수정하러 다시 열자 유튜브 카드가 **재생성돼 있었다**
3. 다시 떼고 `업데이트` → 또 열자 유튜브·카카오 카드가 **둘 다 재생성**
4. 편집을 반복하는 동안 매번 다시 뗐다

그래서 카드 없는 링크 글을 예약할 때는:

- **카드 제거는 마지막 `업데이트` 직전에 한다.** 중간 편집에서 떼는 것은 헛수고다.
- 편집하러 열 때마다 "이전에 뗐으니 없겠지"라고 가정하지 말고 **매번 카드 유무를 다시 확인한다.**
- 반대로 카드를 유지하고 싶은 링크는 아무것도 안 해도 된다 — 재생성이 기본값이다.

예약 발행 시점에는 마지막 `업데이트` 때의 카드 상태가 반영된다(마지막 저장에서 뗀 카드는 발행물에도 없음 — **검증 완료**).

실측 (2026-08-08 10:00 예약 글, claude-in-chrome으로 발행 후 확인): 유튜브 링크는 카드를 유지한 채 마지막 저장 → 발행물에도 카드(og 이미지 + `youtube.com` 사이트명)가 그대로 있었다. 오픈카카오 링크는 마지막 저장 직전에 X로 카드를 뗌 → 발행물에는 카드 없이 URL 텍스트만 파란 링크로 남았다. 재생성이 일어나는 건 편집 모드로 다시 열 때뿐이고, 실제 발행에는 반영되지 않는다.

### 예약 글 수정 (2026-07-27 실측)

`임시 저장본`에서 예약 글을 열면 편집 모드이고, 여기서 **자답글 추가와 시각 변경이 둘 다 된다.**

- 자답글 추가: 맨 아래 `스레드에 추가` → 입력. 칸 번호가 `2/3` `3/3`으로 늘어나는 것으로 확인
- 시각 변경: `···` → `예약...` → 분 부분 삼중클릭 후 타이핑 → `완료`
- 마지막에 **`업데이트`**를 눌러야 반영된다. 누르지 않고 창을 닫으면 확인창이 뜨고, 거기서 `취소`하면 작성창이 유지된다

예약 시각 직전에도 수정이 먹힌다(발행 3분 전에 자답글 추가 + 10분 미루기 성공).

## 2. 예약한 글을 다시 찾기

**프로필에서 새 글 작성창을 열고 `임시 저장본` 버튼(작성창 우측 상단 문서 아이콘)을 누른다.** 예약 글이 그 목록에 있고, 클릭하면 편집 모드로 열린다. 하단 버튼이 `게시`가 아니라 **`업데이트`**면 편집 모드가 맞다.

`예약`을 누른 직후에도 이 경로가 **유일한 확인 수단이다** (2026-08-01, Aside repl). 작성창이 닫히기만 하고 토스트도 배너도 남지 않아 성공 여부가 화면에 안 보인다. 목록에서 `월요일 오후 7:00 GMT+9에 게시 예정`과 `답글 n개`를 눈으로 확인한다.

**목록 컨테이너의 `innerText`를 통째로 뜨면 같은 항목이 두 번 나온다** (2026-08-16, claude-in-chrome). 래퍼가 중첩돼 본문과 `게시 예정` 배너, 이미지까지 2회씩 잡힌다. 예약을 한 번만 눌렀는데 중복 등록된 것으로 오판하기 쉽다. **항목 수는 스크롤해서 눈으로 센다.** 텍스트 카운트(`match(/게시 예정/g).length`)를 항목 수로 쓰지 않는다.

`임시 저장본` 버튼은 `innerText`가 비어 있어 텍스트로 찾을 수 없다. 자식 `svg`의 `aria-label`로 찾는다:

```javascript
[...document.querySelectorAll('div[role="dialog"] div[role="button"]')]
  .find(b => b.querySelector('svg[aria-label="임시 저장본"]'))
```

여기에 **없는** 곳(전부 확인해본 헛수고):

- 왼쪽 사이드바 `더 보기` → 디자인/설정/좋아요/보관함/문제 신고/로그아웃뿐
- 프로필 우측 상단 `···` → `열로 추가`뿐
- 프로필 피드 → 예약 글은 표시되지 않음
- `https://www.threads.com/settings/scheduled_posts` → 404

작성창이 예약 글을 물고 있으면 다른 곳을 클릭할 때 `예약된 게시물을 업데이트하시겠어요?` 확인창이 뜬다. 더 고칠 예정이면 **`취소`**를 눌러 작성창을 유지한다. `업데이트`를 누르면 그 시점 내용으로 확정되고 창이 닫힌다.

## 3. API로는 예약이 안 된다

Threads 공식 API에 예약 발행 기능이 없다. API로 하려면 스케줄러(launchd 등)를 직접 만들어야 하므로, 일반 글은 웹의 `예약`을 쓰는 쪽이 확실하다.
