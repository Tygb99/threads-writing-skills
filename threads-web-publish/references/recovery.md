# 발행 후 수정과 사고 복구



`threads-web-publish` 상세 참조. 잘못 올렸거나 답글을 고정·수정할 때 읽는다.



---

## 1. 잘못 올렸을 때

**15분 안에 `수정`으로 복구한다** (점 3개 → 수정 → 완료). 삭제하지 않는다 — 삭제하면 그때까지 붙은 노출과 반응이 같이 사라지고, 같은 글을 다시 올려도 알고리즘이 처음부터 다시 시작한다.

### 답글 수정으로는 이미지를 추가할 수 없다 (2026-07-31, Aside repl)

이미 올린 답글의 `···` → `수정` 창에는 **미디어 첨부 버튼이 없고 `Cmd+V` 클립보드 붙여넣기도 무반응이다.** 텍스트만 고칠 수 있다.

이미지를 넣으려면 답글을 새로 올려야 한다. 안전한 순서는:

> **이미지 포함 답글을 먼저 게시 → 기존 답글 삭제 → (필요하면 새 답글 고정)**

새 답글을 먼저 올리므로 중간에 댓글이 비는 구간이 없다.

수정창을 `취소`하면 `수정 사항을 삭제하시겠어요?` 확인창이 뜬다. 거기서 `삭제`를 눌러도 **원 답글은 그대로 유지되고 수정 내용만 버려진다.**

---

## 2. 답글 고정 — 교체할 때 확인창이 뜬다 (2026-07-31, Aside repl)

답글 고정은 답글의 `···` → `답글 고정`이다. 고정이 처음이면(기존 고정 없음) 확인창 없이 바로 적용된다.

**이미 고정된 답글이 있으면 확인창이 뜬다:**

> `현재 고정된 메시지를 바꾸시겠어요? / 한 번에 하나의 답글만 스레드에 고정할 수 있습니다.`

이 창의 `확인`을 누르지 않으면 **고정이 조용히 무효화된다.** 오류 메시지가 없고 메뉴만 닫히므로, `고정됨` 배지가 없는 것을 보고 "고정 기능이 안 된다"고 오판하기 쉽다. 실제로 이 확인창을 놓쳐 **4회 연속 실패**했다 — DOM click, 좌표 클릭, pointer 이벤트 시퀀스, locator ref 클릭 모두 같은 결과였다. 클릭 방식이 문제가 아니었다.

절차:

1. `···` → `답글 고정` 클릭
2. **`div[role="dialog"]` 존재를 확인**한다. 있으면 `확인`을 누른다
3. 그 뒤 새로고침 한 번으로 `고정됨` 배지를 확인한다

## 3. 되돌릴 수 없는 클릭 전에는 정체를 확인한다

`find`가 돌려주는 설명은 **접근성 트리와 주변 텍스트에서 추론한 것**이지 확인된 사실이 아니다. 특히 `button "(no name)"`은 그 요소에 이름이 없다는 뜻이라, 붙은 설명일수록 근거가 약하다.

2026-07-29에 "링크 카드의 삭제 버튼"이라고 설명된 `(no name)` 버튼을 눌렀더니 **`게시`였다.** 예약하려던 글이 그 자리에서 발행됐다.

`게시`·`삭제`·`저장 안 함`처럼 되돌릴 수 없는 자리에서는 클릭 전에 확인한다:

```javascript
const el = /* find가 준 ref의 요소 */;
JSON.stringify({
  text: el.innerText,
  aria: el.getAttribute('aria-label'),
  rect: el.getBoundingClientRect(),                    // 어디에 있는 버튼인가
  inDialog: !!el.closest('div[role="dialog"]')
})
```

**위치만 봐도 대개 갈린다.** 카드를 떼는 버튼이 작성창 맨 아래 `게시` 자리에 있을 리 없다.

### 작성창이 사라지면 발행부터 의심한다

**닫힘과 발행은 화면상 구분이 안 된다.** 사라진 직후 **프로필 피드 최상단**을 먼저 확인한다. 임시 저장본을 뒤지는 건 그다음이다.

이 순서를 뒤집으면 "초안이 날아갔다"고 오판하고 같은 글을 다시 쓰게 된다 — 중복 발행 직전까지 간 적이 있다.

**사용자가 "게시된 것 같다"고 말하면 그 말이 내 화면 판단보다 우선한다.** 즉시 피드를 확인하고, 확인될 때까지 다음 입력을 하지 않는다.
