`threads-web-publish` 상세 참조. 잘못 올렸거나 답글을 고정·수정할 때 읽는다.

## 1. 잘못 올렸을 때

**15분 안에 `수정`으로 복구한다** (점 3개 → 수정 → 완료). 삭제하지 않는다 — 삭제하면 그때까지 붙은 노출과 반응이 같이 사라지고, 같은 글을 다시 올려도 알고리즘이 처음부터 다시 시작한다.

### `수정`은 두 개가 있다 — 게시물 메뉴 안의 것만 눌러라 (2026-08-13, claude-in-chrome)

DOM에 `수정` 텍스트를 가진 요소가 둘이다: 게시물 `···` 메뉴의 **게시물 수정**과, **좌측 사이드바의 "피드 수정"**. `querySelector`로 첫 번째 `수정`을 잡으면 사이드바의 피드 편집 다이얼로그("피드를 끌어다 놓아 순서를 변경하세요")가 열린다. 반드시 **게시물 메뉴(`div[role="menu"]`) 내부로 스코프를 좁혀서** 잡거나, 스크린샷으로 메뉴 안 "수정 HH:MM"(편집 시각 배지가 붙은 항목)을 좌표로 누른다.

### 수정창은 Lexical이라 DOM 삭제가 안 먹는다 — 키보드로 비운다 (2026-08-13)

본문을 통째로 갈아끼울 때 `range.selectNodeContents(el)+execCommand('delete')`나 TreeWalker 삭제는 **먹지 않는다**(길이가 그대로다). 확실한 방법은 입력칸 포커스 후 **`cmd+A` → `Delete` 키**로 비우고 새로 타이핑하는 것이다. 비운 뒤 길이가 0인지 확인하고 입력한다.

### 본문을 훅까지 줄이고 나머지를 답글로 내리기 (2026-08-13)

긴 글의 도달이 낮을 때, 본문을 **궁금증이 걸리는 지점**("…네 개였습니다.")까지 줄이고 나머지를 자답글로 내리면 "무슨 네 개?"가 걸려 답글 조회·체류가 는다. 절차: ① 게시물 `···` → 게시물 수정 → cmd+A·Delete로 훅까지만 남기고 완료 ② 답글칸의 **확장(⤢) 아이콘**으로 확장창을 열어(인라인 Enter=즉시 게시 회피) 나머지를 붙인다. 원 글의 노출·반응이 유지되므로 삭제보다 낫다.

### 답글 수정으로는 이미지를 추가할 수 없다 (2026-07-31, Aside repl)

이미 올린 답글의 `···` → `수정` 창에는 **미디어 첨부 버튼이 없고 `Cmd+V` 클립보드 붙여넣기도 무반응이다.** 텍스트만 고칠 수 있다.

이미지를 넣으려면 답글을 새로 올려야 한다. 안전한 순서는:

> **이미지 포함 답글을 먼저 게시 → 기존 답글 삭제 → (필요하면 새 답글 고정)**

새 답글을 먼저 올리므로 중간에 댓글이 비는 구간이 없다.

수정창을 `취소`하면 `수정 사항을 삭제하시겠어요?` 확인창이 뜬다. 거기서 `삭제`를 눌러도 **원 답글은 그대로 유지되고 수정 내용만 버려진다.**

### 수정으로는 링크 카드도 뗄 수 없다 (2026-07-31, Aside repl)

본문에 쓴 문자열이 도메인처럼 보이면 링크 카드가 붙는다. `api.codewhisperer.profile` 같은 설정 키를 그대로 적었더니 카드가 생겼다.

수정창에는 **카드를 떼는 `X` 버튼이 없다.** 작은 버튼은 창 닫기와 더 보기뿐이라, 카드만 골라 지울 수 없다.

**뒤집으면 이렇다 — 게시할 때 뗀 카드는 그대로 유지된다** (2026-08-23 사장 실측, claude-in-chrome 교차 확인).
최초 작성창에서 X로 뗀 뒤 게시하면, 그 뒤 **수정창을 열어 카드가 다시 보이더라도 그건 미리보기일 뿐**이고 발행본에는 붙지 않는다.
post30 자답2(`DcYBcwaEyfd`)는 게시 때 한 번 떼고 발행 후 두 번 더 고쳤는데, 매 수정 모달에 카드가 보였지만 **게시물 페이지·공식 API 어디에도 카드가 없었다.**

> **규칙: 링크 카드를 뗄 기회는 최초 게시 때 한 번뿐이다. 그때 반드시 뗀다.**
> 수정 단계에서 카드가 보인다고 당황해 텍스트를 건드리지 마라 — 고칠 수단이 없고, 실제로는 붙지도 않았다.

유일하게 통한 방법은 **링크 패턴 자체를 깨는 것**이다:

> 칸을 비우고, 점 앞뒤에 공백을 넣어 다시 타이핑한다. `api . codewhisperer . profile`

`Meta+a` → `Backspace`로 칸을 비우면 카드도 같이 사라진다. 그 상태에서 공백을 넣은 문자열로 다시 쓰면 카드가 재생성되지 않는다.

**게시 직후 화면에는 카드가 남아 보일 수 있다** — Threads 캐시다. 본문 텍스트가 바뀌었는지로 판단하고, 카드 잔상만 보고 실패로 오판하지 않는다.

애초에 설정 키·도메인 형태 문자열을 쓸 일이 있으면 **처음부터 점 앞뒤에 공백을 넣거나 따옴표로 감싸** 카드가 안 생기게 한다.

## 2. 답글 고정 — 교체할 때 확인창이 뜬다 (2026-07-31, Aside repl)

답글 고정은 답글의 `···` → `답글 고정`이다. 고정이 처음이면(기존 고정 없음) 확인창 없이 바로 적용된다.

**이미 고정된 답글이 있으면 확인창이 뜬다:**

> `현재 고정된 메시지를 바꾸시겠어요? / 한 번에 하나의 답글만 스레드에 고정할 수 있습니다.`

이 창의 `확인`을 누르지 않으면 **고정이 조용히 무효화된다.** 오류 메시지가 없고 메뉴만 닫히므로, `고정됨` 배지가 없는 것을 보고 "고정 기능이 안 된다"고 오판하기 쉽다. 실제로 이 확인창을 놓쳐 **4회 연속 실패**했다 — DOM click, 좌표 클릭, pointer 이벤트 시퀀스, locator ref 클릭 모두 같은 결과였다. 클릭 방식이 문제가 아니었다.

절차:

1. `···` → `답글 고정` 클릭
2. **`div[role="dialog"]` 존재를 확인**한다. 있으면 `확인`을 누른다
3. 그 뒤 새로고침 한 번으로 `고정됨` 배지를 확인한다

## 3. 되돌릴 수 없는 클릭 전에는 정체를 확인한다

`find`가 돌려주는 설명은 **접근성 트리와 주변 텍스트에서 추론한 것**이지 확인된 사실이 아니다. 특히 `button "(no name)"`은 그 요소에 이름이 없다는 뜻이라, 붙은 설명일수록 근거가 약하다.

2026-07-29에 "링크 카드의 삭제 버튼"이라고 설명된 `(no name)` 버튼을 눌렀더니 **`게시`였다.** 예약하려던 글이 그 자리에서 발행됐다.

`게시`·`삭제`·`저장 안 함`처럼 되돌릴 수 없는 자리에서는 클릭 전에 확인한다:

```javascript
const el = /* find가 준 ref의 요소 */;
JSON.stringify({
  text: el.innerText,
  aria: el.getAttribute('aria-label'),
  rect: el.getBoundingClientRect(),                    // 어디에 있는 버튼인가
  inDialog: !!el.closest('div[role="dialog"]')
})
```

**위치만 봐도 대개 갈린다.** 카드를 떼는 버튼이 작성창 맨 아래 `게시` 자리에 있을 리 없다.

### 작성창이 사라지면 발행부터 의심한다

**닫힘과 발행은 화면상 구분이 안 된다.** 사라진 직후 **프로필 피드 최상단**을 먼저 확인한다. 임시 저장본을 뒤지는 건 그다음이다.

이 순서를 뒤집으면 "초안이 날아갔다"고 오판하고 같은 글을 다시 쓰게 된다 — 중복 발행 직전까지 간 적이 있다.

**사용자가 "게시된 것 같다"고 말하면 그 말이 내 화면 판단보다 우선한다.** 즉시 피드를 확인하고, 확인될 때까지 다음 입력을 하지 않는다.
