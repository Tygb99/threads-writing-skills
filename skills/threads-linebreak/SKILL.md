# Threads 줄바꿈

## 언제 쓰는가

Threads 본문, 자답, 답글을 쓰거나 고칠 때 사용한다. 두 문장 이상이면 적용하고 한 줄짜리 짧은 답글은 예외로 둔다. Instagram, X, 블로그 문안에는 적용하지 않는다.

Threads 피드는 모바일 세로 화면에서 스크롤로 읽힌다. 줄바꿈은 장식이 아니라 읽기 속도를 만드는 구조다. 이 규칙의 근거는 게시물 397건의 줄 단위 집계다.

## 핵심 규칙

- 한 줄 목표는 25자, 상한은 40자다. 글자 수에서 줄바꿈은 제외한다.
- 문단은 빈 줄 하나로 나누고 최대 4줄로 둔다. 1~2줄을 권장한다.
- 연결어미 뒤 절 경계 쉼표에서 줄을 바꾼다. 숫자, 나열, 짧은 동격의 쉼표는 줄 중간에 둔다.
- 문장 끝 마침표는 생략한다. URL, 수치, 버전, 파일명 안의 점은 보존한다.
- 해시태그는 붙이지 않는다. 필요한 경우의 예외는 마지막 단독 문단뿐이다.

## 쉼표 판단

모든 쉼표에서 줄을 바꾸지 않는다. 연결어미 뒤 쉼표는 다음 절을 새 줄에서 시작한다. 대표적인 연결어미는 `-는데,`, `-하고,`, `-지만,`, `-는지,`, `-면서,`, `-라서,`, `-아서,`, `-어서,`, `-니까,`, `-고,`, `-며,`다.

숫자 쉼표(`1,`, `2,`), 영문 약어 뒤 쉼표, 짧은 나열과 동격을 잇는 쉼표는 줄 중간에 둔다. 줄 끝 쉼표는 전체 쉼표의 절반 이하가 정상이며 절반을 넘으면 과용이다.

절 경계 예시는 다음과 같다

```
크롬 원격은 구글이 죽였고,
다른 앱은 PC에 서버를 깔아야 했다
```

나열 예시는 쉼표를 같은 호흡에 둔다

```
2024년, 국민연금공단 면접장
3년, 4년, 2년을 차례로 적었다
```

한 줄에 두 종류가 같이 올 수 있다

```
윈도우 11도, 내 Mac mini도,
데스크톱 앱 없이 인터넷 권한 없이
```

`11도,`는 나열이라 유지하고 `Mac mini도,`는 절 경계라 다음 줄로 보낸다. 쉼표 개수가 아니라 무엇을 잇는지 판단한다.

## 문단과 마침표

문단은 생각 하나를 담고 빈 줄 하나로 나눈다. 1~2줄을 권장하고 최대 4줄까지 허용한다. 5줄이면 생각 단위로 쪼갠다.

문장 구분은 줄바꿈으로 드러낸다. 문장 끝 마침표는 생략하되 URL, 소수, 버전, 파일명 안의 점은 보존한다.

## 해시태그

해시태그는 붙이지 않는다. 150건 대조에서 해시태그 있음과 없음의 조회 중앙값이 910과 902로 차이가 없어 기본 규칙에서 제외했다. 검색 유입을 일부러 노릴 때만 예외로 두며, 그때도 마지막 단독 문단에 놓고 자답글에는 0개를 둔다.

## 적용 절차

1. 내용을 먼저 완성한다. 줄바꿈은 마지막 공정이다.
2. 생각 단위로 문단을 나누고 빈 줄 하나를 둔다.
3. 40자를 넘는 줄을 절 경계 쉼표에서 끊는다.
4. 숫자·나열 쉼표는 끊지 않았는지 확인한다.
5. 문장 끝 마침표와 해시태그를 현재 규칙에 맞게 정리한다.
6. 검사기를 실행하고 판단 보류 후보는 문맥으로 확인한다.

## 첫 문단 지침

첫 문단은 1~2줄을 권장한다. 첫 줄은 문장 종결어미로 끝내지 않는 미완결 형태를 권장하고, 숫자와 따옴표 포함 여부를 확인한다. 주어가 사건인지 작업물인지는 사람이 정한다.

| 항목 | 조회 중앙값 |
|---|---:|
| 주어 사건형 | 940 |
| 주어 기타 | 866 |
| 주어 작업물형 | 207 |
| 첫 문단 1줄 | 878 |
| 첫 문단 2줄 | 933 |
| 첫 문단 3줄 이상 | 565 |
| 첫 줄 미완결 | 914 |
| 첫 줄 완결 | 746 |
| 숫자 있음 | 927 |
| 숫자 없음 | 705 |
| 따옴표 있음 | 936 |
| 따옴표 없음 | 826 |

위 수치는 129건의 중앙값이다. 첫 문단 글자 수는 조회와 상관이 없다. 만든 것을 알리고 싶으면 그것을 만들게 된 사건을 앞에 세운다. 주어 판정은 검사기가 대신하지 않는다.

## 검사기 사용법

스크립트는 인자로 받은 파일 하나 또는 표준입력만 읽으며 파일을 탐색하지 않는다. 옵션, 출력 항목, 상수, 종료 코드는 각 검사기의 `--help`를 정본으로 삼는다.

```bash
python3 scripts/check_linebreaks.py draft.txt
cat draft.txt | python3 scripts/check_linebreaks.py
python3 scripts/check_linebreaks.py draft.txt --json
python3 scripts/check_first_paragraph.py draft.txt
python3 scripts/check_first_paragraph.py draft.txt --json
```

줄바꿈 검사기는 40자 초과, 4줄 초과 문단, 해시태그 위치를 위반으로 보고한다. 줄 길이·문단 길이·줄 끝 분포와 쉼표 판단 보류 후보도 표시한다. 위반 없음은 exit 0, 위반 또는 빈 입력은 exit 1이다.

첫 문단 검사기는 줄 수, 첫 줄 미완결, 숫자, 따옴표의 형태만 표시한다. 첫 문단 3줄 이상만 exit 1이다. 주어의 사건형·작업물판정은 기본으로 하지 않는다.

### Jev 판정 (실험, `--jev`)

두 검사기에 `--jev`를 주면 사람에게 넘기던 판정을 Jev(TypeSafe System One 모델, Vercel AI Gateway `typesafe-ai/jev`)에게 먼저 묻는다. 환경변수 `AI_GATEWAY_API_KEY`가 필요하며 없으면 exit 2다. 판정 실패 시에는 규칙 휴리스틱으로 대체하고 stderr에 이유를 남긴다.

```bash
AI_GATEWAY_API_KEY=... python3 scripts/check_linebreaks.py draft.txt --jev
AI_GATEWAY_API_KEY=... python3 scripts/check_first_paragraph.py draft.txt --jev
```

- 줄바꿈 검사기: 모든 쉼표를 절 경계/나열로 판정해 실제 줄 위치와 어긋나는 것만 confidence 순으로 보여준다. 모델에는 줄바꿈을 지운 문단만 보낸다.
- 첫 문단 검사기: 주어 유형(사건형/작업물형/기타)과 첫 줄 미완결 확률을 덧붙인다.
- 아카이브 207개 쉼표 실측(2026-09-22): 줄 위치 라벨과 73.7% 일치, confidence 0.7 이상 70%를 추리면 78.5%. 나열은 90% 잡지만 `~했고, ~했고,` 같은 병렬 절은 나열로 보는 경향이 있다. 확신 높은 불일치 대부분은 규칙 이전 글이 나열을 줄 끝에 둔 경우였다.
- Jev 값은 볼 순서를 정할 뿐이다. 최종 판단과 문자 단위 대조는 여전히 사람이 한다.

## 완성 예시

```
오늘 아침 배포가 두 번 실패했고,
원인은 환경변수 하나였다

고치는 데 3분, 찾는 데 2시간

값을 확인하니 공백 하나가 남아 있었다
다음 배포부터는 시작 전에 검사한다
```

절 경계 쉼표는 줄 끝에 두고 문장 끝 마침표와 해시태그는 넣지 않았다. 나열 쉼표는 같은 줄의 호흡을 유지한다.

## 알아둘 것

- 글자 수는 줄바꿈을 제외하고 센다. 줄바꿈을 늘려도 본문 길이에는 영향이 없다.
- 본문 길이 구간 규칙은 두지 않는다. 같은 계정 169건 재검증에서 글자 수와 조회의 상관은 0이었고(rho -0.006), 한때 "골든존"으로 불린 151~280자 구간의 조회 중앙값(821)은 0~150자(943)·281~350자(1,261)보다 낮았다. 길이는 소재가 정하지 규칙이 정하지 않는다.
- Threads 인라인 답글창에서 Enter는 줄바꿈이 아니라 즉시 게시다. 여러 줄은 확장 작성창이나 Shift+Enter를 사용한다.
- 본문, 자답, 답글에 같은 줄바꿈 규칙을 적용한다.
- 줄바꿈을 고친 뒤에는 문자 단위로 원문과 대조한다.
- 다른 채널인 Instagram, X, 블로그에는 이 규칙을 옮기지 않는다.
