# Threads 웹 발행

## 언제 쓰는가

Threads 웹 작성창을 열어 본문·자답글·첨부를 입력하고 게시·예약·수정할 때 쓴다.
예약본 조회, 인용카드, 답글 고정, 동의받은 DM 소재 확인도 포함한다.
요청이 이미 허용한 작업은 그대로 수행하고, 문안 작성 요청을 게시나 DM 전송 허가로 확대하지 않는다.

## 전제: Aside

- Aside 앱이 실행 중이고 대상 Threads 계정에 로그인돼 있어야 한다.
- 먼저 `aside guide`를 읽고, 직접 조작할 때는 `aside guide repl`도 읽는다. CLI 사용법은 이 출력이 정본이다.
- 기본은 `aside exec` 위임이다. 스킬 절대경로, 칸별 정본 텍스트·사진·alt 파일 절대경로, 읽기 전용/쓰기 범위, 중복 방지 조건과 보고 형식을 넘긴다.
- 화면과 DOM을 직접 확인해야 하는 단계만 `aside repl`을 쓴다. 실행 양식과 파일 접근은 [Aside 준비](references/aside-setup.md)에 있다.
- 사용자 제공 입력은 UTF-8 텍스트 파일, 첨부 파일, 대상 계정·게시물, KST 예약 시각이다. 칸과 첨부 순서를 명시하며 임의의 폴더를 뒤져 초안을 찾지 않는다.

## 절대 규칙

1. 작업 중 새로고침하지 않는다. 상태 확인은 새 `snapshot()`과 스크린샷으로 한다.
2. 인라인 답글창에서 Enter는 즉시 게시다. 여러 줄은 확장 작성창에서 입력한다. 인라인이 필요하면 줄마다 `Shift+Enter`를 쓴다.
3. `@` 멘션 팝업이 뜬 동안 Enter는 후보 선택이다. 맞는 후보를 클릭해 확정하고 붙은 꼬리 공백을 제거한 뒤 줄바꿈한다.
4. 팝업은 해당 X로 닫는다. X 없는 멘션은 후보 클릭이나 커서 이동으로 정리한다. Escape는 작성창까지 닫을 수 있다. 계속 작업할 때 확인창은 `취소`로 닫는다. `저장 안 함`은 복구할 수 없다.
5. 본문·자답글·alt·텍스트 첨부의 모든 칸을 정본과 문자 단위로 대조한다. 글자 수 일치만으로 통과시키지 않는다.
6. 해시태그는 기본 0개다. 주제 태그는 글당 1개 모델이므로 본문에 여러 개를 넣지 않는다.
7. 댓글의 뜻은 `{id}/conversation` 전문을 시간순으로 읽어 판단한다. 첨부는 API의 `media_type`·`media_url`·`alt_text`로 확인한다. 규칙이나 썸네일만으로 확정하지 않는다.
8. 사용자도 같은 브라우저를 조작한다. 화면의 결과가 내 행동 때문이라고 단정하지 않는다. 모르는 값·주체·성공 여부는 `미확인`으로 보고한다.
9. 행동 직전에 `TZ=Asia/Seoul date`로 시각을 다시 확인한다. `방금` 같은 표현과 예약 시각을 현재 시점에 대조한다.
10. 같은 첫 줄의 글이 이미 있으면 게시하지 말고 보고한다. 작성창이 사라졌거나 사용자가 게시됐다고 말하면 입력을 멈추고 프로필 최상단부터 확인한다.

## 표준 절차

### 1. 초안 확보

1. 대상 계정, 본문과 자답글 순서, 칸별 사진·영상·alt, 게시/예약/임시 저장 중 요청한 작업을 확인한다.
2. 정본 파일은 게시할 텍스트만 담는다. 불필요한 파일 끝 개행 없이 준비하고, 내용 변경은 사용자 지시 범위에서 한다.
3. 줄바꿈은 `threads-linebreak`의 `<plugin-root>/skills/threads-linebreak/SKILL.md`를 따른다.
4. 발행 간격은 **기본 2시간이며 사용자 지시가 우선**이다. 프로필 최신 글과 임시 저장본 예약 목록을 먼저 확인하고 가장 늦은 시각에서 2시간 이후로 배치한다.
5. 사용자가 “게시해”라고 명시하면 그 1회는 간격 예외로 즉시 게시한다. 이후 기본 간격은 유지한다.

### 2. 작성창 열기

1. 계정과 기존 글의 첫 줄을 확인해 중복을 막는다. 예약본 수정은 새 글 작성창의 `임시 저장본`에서 해당 항목을 연다.
2. 새 글 모달은 자체가 작성창이다. 답글은 인라인의 확장 버튼으로 연다. 확장 작성창은 `role="menu"`일 수 있으므로 `dialog`만 검색하지 않는다.
3. 새 snapshot에서 대상 작성창·입력칸을 찾는다. 클릭한 뒤 `activeElement`가 해당 `contenteditable` 인덱스인지 확인한다.

### 3. 입력과 문자 대조

1. 여러 줄은 `keyboard.type`으로 통째로 입력한다. 멘션 팝업이 생기는 부분은 멈추어 후보 클릭·꼬리 공백 정리를 마친 뒤 이어 쓴다. `execCommand('insertText')`는 개행을 무시한다.
2. 한 곳 치환은 선택 영역 `delete` 후 `insertText`로 한다. 두 곳 이상이면 해당 칸을 비우고 다시 타이핑한다. 한글은 리터럴로 전달한다.
3. 자답글은 `스레드에 추가`로 칸을 늘려 한 번에 게시한다. 밀려난 버튼은 스크롤 후 스크린샷으로 위치를 확인하고, 클릭 뒤 본문 `contenteditable` 개수가 늘었는지 확인한다.
4. 각 칸의 `innerText`를 UTF-8 파일로 저장해 `scripts/compare_text.py`로 비교한다. 본문 끝 개행은 서버가 제거하므로 작성창에서 지우지 말고 실제 값에만 `--rstrip-actual`을 적용한다.
5. 차이가 있으면 첫 차이 위치부터 고치고 전 칸을 다시 대조한다. [입력·첨부 절차](references/composing.md)에 실행 예가 있다.

### 4. 사진과 alt

1. 외장 저장소의 파일은 호출 측 셸에서 현재 Aside 세션의 tmp로 복사한 뒤 `input[type=file]`에 `setInputFiles`로 넣는다.
2. 실사는 JPEG 긴 변 2000px 이내·품질 85~90, 스크린샷은 PNG다. WebP는 PNG로 변환한다. EXIF 방향은 `ImageOps.exif_transpose`로 픽셀에 반영한다.
3. 단독 1장은 원본 비율을 유지한다. 2장 이상은 같은 4:5 비율로 패딩해 잘림을 막는다. 업로드 실패는 실제 발행 여부부터 확인하고 용량을 줄여 재시도한다.
4. 영상은 MP4를 같은 경로로 첨부한다. `video.readyState=4`, 실제 크기, `duration`을 폴링해 준비 완료를 확인한다.
5. 사진·영상마다 `··· → 대체 텍스트 추가 → 입력 → 완료`를 수행한다. alt 문안은 `alt-text-generator`의 `<plugin-root>/skills/alt-text-generator/SKILL.md`를 따른다.
6. 저장된 이미지 `img.alt`와 영상 `aria-label`을 정본과 대조한다. 발행 후 alt를 고칠 수 없으므로 게시 전에 끝낸다.
7. 예약 초안에서 alt만 바꿔 `업데이트`가 비활성이면 본문 끝에 임시 문자를 추가해 저장하고, 다시 열어 그 문자만 제거해 재저장한다. 본문·alt·예약 시각을 재확인한다.

### 5. 예약 또는 게시

1. `CLAUDE.md`처럼 파일명인 낱말도 링크 카드가 된다. 원치 않는 카드는 마지막 `예약`·`업데이트`·`게시` 직전에 X로 제거한다. 임시 저장본을 다시 열면 재생성된다.
2. 인용카드와 텍스트 첨부는 예약할 수 없다. 텍스트 첨부는 10,000자 한도이며 개행은 2자로 센다. 사진·GIF·설문·음악과 함께 쓸 수 없다.
3. 예약은 `··· → 예약... → 날짜 → 시·분 → 완료`다. 시·분은 24시간제로 `locator.fill()`하고 값과 KST 배너를 대조한다.
4. `게시`는 현재 작성 dialog 안에서 찾는다. 확장 답글이 menu인 경우에는 확인한 작성 menu로 한정한다. 피드의 같은 이름 버튼을 누르지 않는다.
5. 버튼을 한 번 누르고 새 snapshot에서 작성창 소멸을 확인한다. 창이 닫히면 프로필 최상단을 확인하고, 예약이면 임시 저장본 목록에서 해당 항목과 예정 시각을 확인한다.
6. 창 소멸만으로 성공을 확정하지 않는다. 결과가 불분명하면 재게시하지 말고 [복구 절차](references/recovery.md)를 따른다.

### 6. 발행 후 검증

1. 즉시 화면에서 permalink, 칸 순서·개수, 사진·영상, 카드 상태를 확인한다.
2. **발행 시각 +16분 이후** 공식 API로 각 글의 문자·`media_type`·`media_url`·`alt_text`를 확정 대조한다. 토큰은 `THREADS_ACCESS_TOKEN` 환경변수로 받으며 [검증 절차](references/recovery.md#공식-api-확정-검증)를 따른다.
3. 15분 수정 창 안의 변경은 차이만 기록한다. 이를 자동으로 오류나 내 조작의 결과로 단정하지 않는다.
4. API 확인 전에는 “화면 확인 완료, API 미확인”과 +16분 확인 예정 KST 시각을 보고한다. 토큰이나 실행 수단이 없으면 그 이유를 명시한다.
5. 24h·72h 성과 크론은 없다. 이 스킬로 새 성과 타이머를 만들지 않는다.

## 발행 전 점검표

- [ ] 작업 범위와 계정이 맞고, 같은 첫 줄의 기존 글이 없는가.
- [ ] 최신 글·예약 목록과 기본 2시간 간격 또는 이번 사용자 예외를 확인했는가.
- [ ] 답글 확장창, 멘션 후보 클릭·꼬리 공백 제거, 정확한 입력칸 포커스를 확인했는가.
- [ ] 본문·자답글·텍스트 첨부·alt 전부를 정본과 문자 단위로 대조했는가.
- [ ] 자답글 칸 수와 순서, 첨부 순서·방향·비율·처리 완료를 확인했는가.
- [ ] 모든 사진·영상 alt를 저장하고 DOM에서 다시 읽었는가.
- [ ] 기본 태그 0개를 지켰고, 원하는 카드만 마지막 저장 직전 남겼는가.
- [ ] 인용카드와 사진을 같은 칸에 쓴다면 카드를 먼저 만들고 사진을 붙였는가. 필요한 인용카드는 게시 직전 복원했는가.
- [ ] 예약을 막는 인용카드·텍스트 첨부가 없고 날짜·입력값·KST 배너가 일치하는가.
- [ ] 이름 없는 버튼은 정체를 확인했고 `게시` 버튼 범위를 작성창으로 좁혔는가.
- [ ] DM 소재는 발화자·입력 경로·게재 동의를 확인했는가.
- [ ] 행동 직전 KST 시각과 발행 후 +16분 검증 계획이 있는가.
